# Shell languages and project maintenance

For a language the game does not support, enable shell translation in the initial translation settings. Enter the actual language, select a supported game language, and choose an output prefix. For example, Italian with the English shell and `it-` produces Italian text loaded through the game's English setting.

**We strongly recommend a separate project for each actual shell language.** No decision is required during project creation. Enabling shell translation shows an expandable, nonblocking notice. Project management shows a compact notice when an archived `custom` language is detected.

Custom languages within a project share the `custom` archive identifier. Alternative names for the same language do not create separate baselines; switching to a different actual language does not isolate existing translations either. The name instructs the translator but is not a baseline identity.

For another shell language, import a fresh copy of the original Mod through Remis. Do not inherit another project's translation-directory associations. Officially supported languages can coexist in the original multilingual project.

This is a recommendation, not a single-language restriction or automatic migration. Enable both the original Mod and translation Mod in the launcher and select the chosen shell language. Verify compatibility in the game.
