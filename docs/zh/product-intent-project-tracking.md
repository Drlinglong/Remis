# Mod 监控：产品意图契约

Mod 监控用来提醒用户：本地磁盘上的 **本地化文件** 发生了变化，可能需要进行增量翻译。
它是只读变化探测器，不是通用文件监控器，也不是自动翻译流水线。当前实现见
[Mod 监控开发契约](developer/project-tracking-contract.md)，使用方法见
[Mod 监控用户指南](user-guides/project-tracking.md)。

## 监控什么

- 只监控本地目录中的本地化文件；
- 本地化文件新增、删除或内容变化时告警；
- 模型、图片、`thumbnail`、游戏机制脚本等非本地化文件不触发告警；
- 仅修改文件时间但内容不变不告警；
- 本地化文件仅在 `localization` / `localisation` 树内移动且内容未变时，理想上不告警；
- 本地化文件中的注释变化会改变文件内容，可以接受告警；增量翻译随后可以得出零新增条目。

当前只考虑本机目录。不监控 Steam 服务器状态，也不依赖作者提供 GitHub Release。

## 监控项与项目

监控项可以不绑定项目，但强烈建议绑定，否则无法自然进入增量翻译。保持最小心智模型：

- 一个规范化目录只能有一个监控项；
- 一个项目默认只绑定一个监控项；
- 没有真实需求前，不支持重复监控同一目录或一个项目配置多个目录。

## 扫描、基线与提醒

第一次扫描只建立当前 SHA-256 基线，显示“开始监控”，不把已有文件当作更新。

支持用户手动扫描、Remis 运行期间的定时扫描和启动时补偿扫描。Remis 退出后不作为
Windows 后台服务常驻；若上次计划扫描在关闭期间错过，下一次启动应立即补扫。

确认有变化后，Remis 记录结果、提醒用户、展示摘要，并提供进入增量翻译的入口。相同变化
只提醒一次，直到用户标记“已处理”或“忽略”。扫描不得自动调用模型、修改文件、启动增量
翻译或部署。

## 错误与生命周期

路径失效、磁盘不可用或权限不足时，保留监控项并显示异常，不自动暂停或删除。

项目归档不影响监控；原 Mod 仍可能更新。项目删除则移除绑定监控，因为它不能再指向幽灵
项目。监控永远只读，发现废弃文件、假本地化或格式错误后也不负责修复。

## Agent 边界

文件是否变化只能由确定性的监控器判断，Agent 不能凭描述或模型推理代替哈希比较。监控
确认变化后，Agent 可以提醒并提出增量翻译计划；当前仍需用户批准后才能执行。未来若引入
明确配置的定时 Agent 工作流，应另立审批、费用和部署契约。
