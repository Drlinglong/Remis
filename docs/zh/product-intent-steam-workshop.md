# Steam 工坊：产品意图契约

这份文档描述 Remis 为什么管理 Steam 工坊发布素材、用户应得到什么，以及素材管理与
真正上传之间的边界。当前实现契约见
[Steam 工坊开发契约](developer/steam-workshop-contract.md)。

## 文档状态

- 产品状态：3.1.x 重建中
- 适用范围：封面图、工坊描述及其项目关联与版本记录
- 产品决定人：玲珑
- 最近确认日期：2026-07-31
- 相关用户指南：[封面图生成器](user-guides/tools-thumbnail-generator.md)
- 后续路线：3.2.x 增加 Steam 上传流水线；完成后再接入 Agent / Copilot

## 产品愿景

封面图和工坊描述不是用完即弃的辅助输出，而是翻译项目的正式发布素材。Remis 应让
用户能够持续保存、比较、采用和找回这些成果，并让未来的发布流水线和 Agent 通过
结构化接口找到它们。

用户最终要完成的是：

1. 为某个翻译项目准备封面图和工坊描述；
2. 在反复生成、编辑后保存可回溯版本；
3. 明确选择准备在下一次发布中采用的版本；
4. 即使尚未创建 Steam 工坊物品，也能先完成并保存素材；
5. 将来由同一工作区把已采用素材交给 Steam 上传流程。

## 入口与信息架构

### 一级入口：Steam 工坊

一级菜单使用“Steam 工坊”，首先进入类似项目管理的发布工作区总览。进入具体工作区后
包含三个同级入口：

- **封面图**；
- **工坊描述**；
- **版本历史**；
- 未来加入 **Steam 上传**；
- 未来加入 **发布记录**。

一级入口服务于跨项目工作：用户可以选择项目，也可以暂不绑定项目创建素材。

### 项目内入口：发布素材管理

在“项目管理 → 具体项目 → 更多视图”的下拉菜单中增加“发布素材管理”。这里展示
当前项目的发布工作区卡片、当前采用版本和可选的 Steam 工坊物品绑定；进入工作区后
使用与一级入口相同的封面图、工坊描述和版本历史页面。

一级入口和项目内入口必须复用同一套数据与组件。项目内入口只是预先锁定项目上下文，
不能发展成第二套独立实现。

## 项目、发布工作区与 Workshop ID

三者必须分离：

- 发布工作区可以选择性绑定一个 Remis 项目；
- 项目不需要拥有 Steam Workshop ID 才能保存发布素材；
- Workshop ID 是发布工作区上的可选远端绑定；
- 新工坊物品在首次上传前没有 Workshop ID，这是正常状态；
- 未绑定项目的工作区可以稍后绑定，绑定后历史版本不得丢失；
- 更换或解除 Workshop ID 不得删除本地素材版本。

界面应鼓励用户选择项目，但允许“暂不绑定”。不得再次使用
`project.workshop_id` 这种把远端标识硬塞进项目对象的隐式契约。

## 版本语义

Remis 使用“可变草稿 + 不可变版本”，不把每次键盘输入或画布拖动都记录为正式版本。

- **草稿**：自动保存，用于崩溃和刷新恢复，可以继续覆盖；
- **候选版本**：由用户保存或一次生成操作产生，不可变；
- **当前采用**：用户明确选择，代表后续发布默认使用的版本；
- **已发布**：未来 Steam 上传成功后，由发布记录引用的精确版本。

切换“当前采用”不会删除其它版本。版本删除、覆盖远端内容或正式上传都不能由普通
草稿保存隐式触发。两类资产的候选版本必须在独立的统一版本历史页面检视和采用，
不能继续堆叠在各自编辑器底部。

## 工坊描述资产

每个正式版本至少保存：

- 可编辑 BBCode；
- 语言；
- 内容 SHA-256；
- 创建时间和来源（手工、模型生成或导入）；
- 父版本；
- 若由模型生成，记录非秘密的 provider/model 元数据；
- 若引用远端原始描述，记录本次生成所使用的源描述快照或其哈希。

模型生成是候选结果，不得自动成为“当前采用”。调用付费模型前必须获得用户明确批准。

## 封面图资产

每个正式版本必须同时保存：

- 可继续编辑的画布结构，包括元素、位置、文字、字体、背景与尺寸；
- 对应的导出图片；
- 图片格式、尺寸和 SHA-256；
- 父版本和来源信息。

只保存 PNG 不足以支持后续修改；只保存画布 JSON 也不足以证明真正交付了哪张图片。

## 成功、失败与安全边界

素材保存成功必须返回工作区、版本号和可找回的结果。模型生成成功但版本保存失败时，
只能报告部分成功；不得让用户误以为成果已经持久化。

3.1.x 明确禁止：

- 自动上传或修改 Steam Workshop；
- 因绑定项目而要求必须填写 Workshop ID；
- 模型生成后自动设为当前采用；
- 把草稿自动保存伪装成正式版本；
- 在删除项目、解除绑定或切换 Workshop ID 时隐式删除版本；
- 把 API 密钥、完整本机敏感路径或未脱敏模型请求写入版本元数据。

## 分期

### 3.1.x

- 建立发布工作区与统一版本模型；
- 重建工坊描述生成器；
- 升级封面图生成器，支持恢复、保存版本和项目关联；
- 提供一级“Steam 工坊”和项目内“发布素材管理”入口；
- 支持选择当前采用版本。

### 3.2.x

- 监控发现有效工作集后进入增量翻译、验证和发布准备；
- 从当前采用版本形成不可变发布快照；
- 经用户明确批准后上传 Steam Workshop；
- 记录 Workshop ID、发布结果、远端状态与失败重试信息。

### 后续大版本

- Agent / Copilot 查询和比较素材版本；
- 生成候选版本并提出采用建议；
- 在用户明确批准后调用正式发布能力。

## 必须长期保留的契约测试

1. 没有项目和 Workshop ID 时仍可创建未绑定发布工作区。
2. 项目绑定不要求 Workshop ID。
3. 项目内入口只展示当前项目发布工作区。
4. 一级入口可以选择项目或暂不绑定。
5. 草稿保存不会创建无限版本；保存版本产生不可变快照。
6. 工坊描述版本保存 BBCode、哈希和来源。
7. 封面图版本同时保存画布结构和导出图片。
8. 选择当前采用版本不删除历史版本。
9. 模型生成必须明确批准，且结果默认只是候选版本。
10. 3.1.x 的素材操作不得产生 Steam 上传副作用。
