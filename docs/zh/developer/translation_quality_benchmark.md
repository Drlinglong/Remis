# Remis 翻译质量基准与阶段路线

## 1. 长期目标与当前决策

Remis 的长期愿景是：在封闭环境中，稳定产出比肩甚至超过人类译者的游戏本地化成果。术语表注入、自动术语抽取、格式校验和自动修复都服务于这个方向。

这是一条长期愿景，不是近期必须完成的“自我进化系统”。现阶段的目标更务实：用很低的工程成本回答三个问题。

1. 对同一批高难度文本，哪个模型的译文风格和语义更好？
2. 哪个模型最擅长修复 Paradox 本地化格式错误？
3. 哪种完整配方最划算，例如“顶级模型一次翻译”和“小模型翻译后再校对”谁的最终效果更好？

当前不因为 prompt 很久未调整就假设它已经最优，也不因为暂时没有高频失败就投入自动调 prompt。先建立可重复观测能力，再由证据决定是否继续。

## 2. 现实约束

- 没有大量归档的历史运行数据。
- 没有大规模人工校对数据和稳定的用户反馈渠道。
- 开发者只有一人，维护成本必须非常低。
- 当前没有明显的高频失败，也没有频繁手动调整 prompt。
- 本地机器一次只能加载一个大模型。
- 开发者无法精通全部 11 种目标语言，语言质量判断需要 LLM 辅助，但不能把 LLM 评分伪装成人类金标。

因此，当前基准是“受控比较工具”，不是学术排行榜，也不是自动修改生产配置的控制器。

## 3. 阶段决策矩阵

| 阶段 | 内容 | 现在是否做 | 启动或升级条件 |
| --- | --- | --- | --- |
| Stage 0 | 固化目标、指标、样本、隐私和停止条件 | 做 | 已具备，本文即为记录 |
| Stage 1 | 统一记录真实运行的输入摘要、模型、prompt 版本、校验和人工修改 | 暂缓 | 有稳定运行量，且记录不会显著增加维护负担 |
| Stage 2 | 冻结 demo 上的多模型翻译、修复和配方基准 | 做 | 已有锁版本 demo 和本地模型 |
| Stage 3 | 产品内匿名 A/B 翻译竞技场，让用户选择偏好 | 候选 | Stage 2 能稳定生成候选；有足够用户或作品集展示需求 |
| Stage 4 | 根据真实运行和偏好数据做失败聚类、prompt 候选实验 | 暂缓 | 已积累足够数据，且出现可重复、高价值失败模式 |
| Stage 5 | 自动生成、评估、灰度和回滚 prompt/配方 | 不做 | 有可靠金标、持续反馈、可审计回滚和明确收益 |

任何阶段都不因“技术上能做”自动升级。升级需要同时满足：问题重复出现、收益可测量、维护成本可承受。

## 4. Stage 2 的三个比较对象

### 4.1 翻译模型

所有模型接收相同源文件、语言方向、游戏配置和 Remis 生产 prompt。首版只抽取少数高复杂度段落，以较低预算观察风格、语义、术语与代码保留能力。

### 4.2 校对/修复模型

所有模型接收相同的源文、同一份人为损坏的译文和相同错误报告。重点比较：能否修完错误、是否破坏原本正确的内容、是否擅自改写风格。

### 4.3 完整翻译配方

最终要比较的单位不是裸模型，而是完整配方：

`翻译模型 + 翻译次数 + 校验器 + 修复模型 + 修复次数 + prompt/config 版本`

例如：

- 顶级模型一次翻译；
- 小模型一次翻译，失败条目再由同一模型修复；
- 翻译专用模型翻译，便宜的小模型负责格式修复；
- 两个候选译文进入匿名 A/B 偏好选择。

## 5. 评分原则

格式不是唯一目标，也不应把“第一次出现格式错误”直接标成技术校验未通过并淘汰整套方案。

### 5.1 基础约束

- 最终结构可解析；
- 条目数一致；
- 变量、作用域、颜色与格式标记最终保持完整；
- 没有明显漏译、增译或方向错误。

首稿格式错误是有效观测值，记入“修复负担”；只有模型调用失败、无法产生可解析结果等情况才算基础设施或执行失败。完整配方以最终输出是否合格为准。

### 5.2 当前主要排序依据

在满足最终基础约束后，优先比较：

1. 语言风格与游戏语境是否合适；
2. 语义忠实度、语气、叙事张力和人物声音；
3. 术语一致性；
4. 修复次数、额外改写和人工介入量；
5. 总耗时与总成本。

语言评审由 Codex 或另一高能力模型匿名比较，输出胜负、置信度和理由。它属于“LLM-as-judge 参考意见”，必须保留原文和候选译文供开发者复核，不作为客观真理。

## 6. 冻结样本

首版 fixture 位于 `tests/fixtures/translation_quality_benchmark_v1.json`。

- Stellaris：先检查本地 `source_mod/Test_Project_Remis_stellaris`，fixture 则固定到同一 demo 谱系的已跟踪 `archive/remis_demo_*.yml`。当前两处文本存在细节差异，因此 archive 是首版基线本身，而不是声称逐字相同的镜像；这样可以避免依赖被忽略的本机目录。
- Victoria 3：`source_mod/Test_Project_Remis_Vic3_Incremental_Frozen`，使用锁版本的简体中文文件。
- 方向：Stellaris 英译中；Victoria 3 中译英。
- 类型：长叙事、对白、术语、方括号作用域、颜色标签、转义换行和引号。

### 6.1 上下文词典样本

`victoria3_contextual_glossary` 使用一段单独冻结的 Victoria 3 风格英文事件，测试三项词典行为：

- `France → 法兰西`：应遵循游戏官方译名，`法国` 记为错误。
- `Texas → 得克萨斯`：应遵循游戏官方译名，`德克萨斯` 记为错误。
- `prestige goods → 名贵商品`：应把它识别为 Victoria 3 的完整经济概念；`威望良好` 记为拆词直译错误。这与地名映射是不同类型的词典遵循测试。
- `silo → 发射井`：fixture 按生产词典结构临时注入，并备注“仅用于军事领域的导弹发射井”；农场事件明确描写麦子且排除军队和导弹，因此正确译法应是`筒仓`。
- `missile silo → 发射井`：同一 case 附带一条明确储存并发射洲际弹道导弹的最小对照文本，此处必须使用`发射井`，不能因为前一个农场语境而一律译成`筒仓`。

第三、四项组成最小对照：同一个 `silo` 术语必须在农业语境中被拒绝、在军事语境中被采用。当前生产词典 prompt 同时写有“必须严格按词典翻译”，所以结果会同时反映模型的语境消歧能力和 Remis prompt 的约束设计。若多个强模型都机械翻成`发射井`，应优先重新审视词典 prompt 是否需要增加“术语适用领域与上下文优先级”，而不是简单认定所有模型都不够聪明。

fixture 不保存 API 密钥。运行结果默认写入被 Git 忽略的 `benchmark_results/`，其中包含源文、模型输出和原始响应，只应保留在本机或经过明确脱敏后分享。

## 7. 单模型顺序运行协议

一次只加载一个模型，完成它的全部冻结样本后卸载，再加载下一个。不要在中途修改 prompt、fixture、LM Studio 推理参数或 Remis provider 配置。

```powershell
python scripts/developer_tools/evaluate_translation_quality.py --dry-run

python scripts/developer_tools/evaluate_translation_quality.py `
  --provider lm_studio `
  --model auto `
  --label "Gemma4-31B-QAT-Q4_0"
```

`--model auto` 在 LM Studio 中会读取本地状态接口的 `loaded_instances`，只有检测到一个已加载实例时才继续；其他 OpenAI 兼容服务则读取 `/models`，如果服务暴露多个模型，必须显式传入真实 API model id。`--label` 只是报告里的可读名称。

计划测试的初始模型：

- Gemma4 31B QAT（Q4_0）
- TranslateGemma 27B Instruct（Q6_K）
- Qwen 3.6 27B（Q4_K_M）
- Nemotron Cascade 2 30B A3B（Q4_K_M）

Nemotron 虽是 agent 模型，但它是常用模型，且本地化文本本身包含代码，因此仍值得纳入。测试的目的正是检验它是否能在没有工具调用干扰的情况下输出稳定译文。

## 8. 可比性与停止条件

每次结果记录 fixture 哈希、实际源文件哈希、prompt 哈希、真实 API model id、可读标签、provider、耗时、原始响应、解析结果和硬校验结果。基线进程会显式清空内存术语表，避免本机可变数据污染比较；术语表注入作为后续独立实验轨道。

以下变化会使两次结果不可直接横向比较：

- fixture 或源文件变化；
- prompt 或格式 prompt 变化；
- 模型量化、上下文长度、采样参数变化；
- 开启了不同的术语表或 provider prompt 前后缀。

Stage 2 的停止条件不是得到一个“永远最强模型”，而是得到足够清楚的配方候选，能支持作品集展示、默认模型建议和下一轮 A/B 比较。若模型差异很小、judge 不稳定或维护成本超过收益，就停留在当前阶段。

## 9. 暂不做的事情

- 不自动修改生产 prompt 或默认模型。
- 不把 LLM judge 分数称为人类质量金标。
- 不为了排行榜批量调用大量云模型。
- 不把真实用户文件自动上传或归档。
- 不在样本不足时训练复杂的自我优化系统。

后续最自然的产品化方向是匿名 A/B 翻译竞技场：Remis 从用户请求中挑选一到数段高复杂度文本，调用两个或多个候选配方并排展示，让用户选择偏好。它既能低成本预览效果，也能逐步积累真实偏好信号。

首轮四个本地模型的实测结果见：[本地模型翻译质量基准报告（2026-07-15）](translation_quality_benchmark_report_2026-07-15.md)。
