# 3.2.1 发布安全复核

复核对象：PR #220 的 CodeQL 告警、动态模块打包，以及受影响路径的回归测试。扫描器对整条数据流的标记不等同于确认可以越界；以下区分实际修复与经核对的预期本地文件操作。未关闭 CodeQL 或修改其规则。

## 实际修复

- 模型回复的数组/对象兜底解析改为线性查找边界，避免对大量未闭合括号执行慢正则；数组元素必须是字符串。
- 工坊描述归档限制标识符为安全单段，检查解析后的归档目录与目标边界，拒绝目录链接逃逸，保留正常的相对路径返回值。
- 原 Mod 的 Workshop 编号限定为 ASCII 数字；解析到的 Workshop 条目必须仍是检测根目录中的同名直接子目录。无效编号不妨碍用户选择真实的本地 Mod。
- 项目元数据文件必须留在用户选定的项目根目录，拒绝 sidecar 文件链接、重解析点或解析后父目录改变；不会禁止正常选择外部项目目录。
- 火星求生 FPK 输入继续使用允许导入目录校验，并使用该校验返回的规范父目录。
- 旧路径翻译入口拒绝文件系统根目录，拒绝覆盖已经存在的同名受管源目录，不再先删除旧目录再复制；拒绝发生在任务创建前。
- 普通翻译 API 的自定义语言配置与 Agent 的约束对齐：显示名称仍可自定义，语言 key 使用已有目录映射，文件夹前缀不能带路径分隔符。输出目录和子目标另做解析后的目录包含校验，内部调用也不能绕过。

## 冻结安装包

PyInstaller 的动态收集参数不足以证明模块已经进包。构建现显式包含游戏工厂和火星求生校验器，并直接检查产物的 PYZ 模块表；缺少 RimWorld、Project Zomboid 或其解析依赖即失败。之后启动真实冻结后端，通过合成 FPK 验证解压、导入计划和隔离应用数据初始化。
