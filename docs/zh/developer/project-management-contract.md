# 项目管理开发契约

本文把[项目管理产品意图](../product-intent-project-management.md)转换为实现约束。用户操作
见[项目管理](../user-guides/project-management.md)；磁盘发现的只读边界另见
[项目文件发现与翻译上载](../product-intent-project-file-discovery.md)。

## 当前实现

- `ProjectManager.create_project()` 创建 UUID 项目，写数据库和源目录下
  `.remis_project.json`，再从磁盘发现文件。
- `import_mode=copy` 只复制游戏配置允许的本地化、元数据和 `thumbnail.png` 等范围；
  `reference` 直接引用用户目录。
- 项目数据库保存名称、游戏、源语言、源路径、目标路径、状态、备注和最近活动。
- `translation_dirs`、源语言和文件看板状态位于项目 sidecar；`.remis_errors.json` 保存
  格式校验结果。
- 文件列表和看板按当前磁盘清单投影；普通刷新不写 `project_files`、归档或 sidecar。
- 前端创建页要求名称、目录、游戏、源语言和导入方式；详情页提供文件、历史、路径、
  校验、备注、项目词典、归档和删除。

目标语言不应新增到 `Project` 固定字段。翻译任务和归档可以按项目记录多个目标语言。

## 数据与副作用

| 操作 | 允许写入 | 禁止副作用 |
|---|---|---|
| 创建项目 | `projects`、项目 sidecar、初始项目历史；复制模式可写工作副本 | 不调用模型，不开始翻译 |
| 刷新文件 | 无；返回实时磁盘清单 | 不修复 sidecar、不上载归档 |
| 元数据检验/重建 | sidecar、看板元数据、必要时错误缓存 | 不修改本地化正文 |
| 修改项目 | `projects`，源语言同步到 sidecar | 不自动重翻或部署 |
| 归档/恢复 | 生命周期状态和项目历史 | 不删除资料，不改变监控启用状态 |
| 删除项目 | 项目记录、项目专属投影和绑定关系 | 不删除独立归档、词典实体、任务或 Arena 历史 |
| 删除磁盘目录 | 仅用户明确确认的准确路径 | 不扩大到父目录或其它路径 |

`ProjectRepository.delete_project()` 当前会删除项目监控快照/绑定、词典绑定、遗留
`project_files`、`ProjectHistory` 和 `ActivityLog`。监控与词典绑定应删除；项目历史与
活动是否保留需迁移为可独立查询的快照，而不能与产品意图冲突后仍宣称完整保留。

## 生命周期

API 只接受 `active` 与 `archived`。归档改变列表可见性，删除使用独立 DELETE。

当前 `update_project_lifecycle_status()` 会在归档时停用所有绑定监控，并在恢复时重新启用。
这与产品决定冲突：监控项目归档不影响本地 Mod 是否更新。应移除
`paused_by_project_archive` 的生命周期联动，并迁移已有标记，保留用户主动启停状态。

## 路径和重复项目

- 所有路径在后端解析、验证并按 Windows 大小写不敏感方式比较。
- 创建前应阻止规范化后相同的 `source_path` 重复登记，返回可定位现有项目的 409。
- 替换路径前必须验证目录存在。sidecar 迁移失败应作为警告返回，不能只写日志后假装完整
  成功。
- 删除磁盘目录前的预览必须返回后端最终解析路径；执行请求必须与预览目标一致。
- `delete_source_files` 默认 `false`。删除确认属于客户端与 Agent action 契约，不能靠
  README 代替。

## 工作流与历史

项目页是初次翻译、增量翻译、校对和部署的共同上下文。入口只负责携带精确 `project_id`
和必要文件身份；具体工作流仍执行各自的预检、付费确认、覆盖确认和持久化任务状态。

未来“最近改动”应聚合结构化的项目历史、Task Center 任务和 Arena 项目快照。不能根据
自由文本日志判断阶段或成功，也不能因项目删除让已有任务记录失去可读的项目名称快照。

## Agent 契约

Agent 创建项目前由用户提供路径；只读识别可以建议名称、游戏和源语言。创建、修改、
归档和恢复仍需 Action Registry 中明确 action 及执行后结果。删除项目与删除目录分别是
高风险批准项，必须展示准确目标。目标语言只能由翻译 action 收集。

## 当前差距

| 产品要求 | 当前事实 | 状态 |
|---|---|---|
| 同一路径只能有一个项目 | 未核验到服务端唯一性检查 | 未实现 |
| 创建时可选登记已有译文目录 | 创建表单当前没有该字段，需另走翻译上载/目录登记 | 未实现 |
| 归档不影响监控 | 当前归档会停用绑定监控 | 冲突 |
| 删除前展示准确磁盘路径并单独确认 | 前端有删除模态框和复选框，需继续锁住预览/执行一致性 | 部分实现 |
| 独立历史不因删项目清空 | 当前删除 `ProjectHistory`、`ActivityLog` | 冲突 |
| 项目页展示最近改动 | 有项目历史组件，但跨任务/Arena 聚合未完成 | 部分实现 |
| 项目页承担四个核心工作流入口 | 已有校对及项目选择链路；需以 UI 回归逐项核验 | 部分实现 |

## 回归门禁

1. 同一路径重复创建返回冲突，原项目和 sidecar 不变。
2. 项目只保存源语言；多个目标语言任务可共用同一 `project_id`。
3. 文件刷新保持只读；元数据修复必须由独立操作触发。
4. 归档与恢复不改变监控项的用户启用状态。
5. 删除项目清理绑定监控和词典绑定，但保留可独立消费的任务、归档与 Arena 记录。
6. 删除磁盘目录默认关闭，确认内容和实际递归删除路径完全一致。
7. 路径缺失返回异常，不把旧项目改写为空。
8. Agent 删除 action 在批准前不得调用 DELETE，也不得把受理当作完成。
