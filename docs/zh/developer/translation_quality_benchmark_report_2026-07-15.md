# Remis 本地模型翻译质量基准报告（2026-07-15）

## 1. 摘要

本轮在 Remis 当前生产翻译与格式修复代码路径上，对四个本地模型进行了同一组冻结样本测试：

- Gemma 4 31B QAT（Q4_0）
- TranslateGemma 27B Instruct（Q6_K）
- Qwen 3.6 27B（Q4_K_M）
- Nemotron Cascade 2 30B A3B（Q4_K_M）

本轮不是为了选出永久的“最佳模型”，而是验证 Stage 2 benchmark 能否区分以下能力：

1. 游戏叙事翻译的语言风格和语义忠实度；
2. Paradox 变量、颜色标签、换行和结构化输出稳定性；
3. 词典术语的正确遵循与上下文消歧；
4. 格式修复模型是否能修好错误且避免擅自重写；
5. 完整运行的延迟成本。

在本轮配置下，Gemma 4 是综合表现最均衡的模型；TranslateGemma 速度优势极大，但质量和格式稳定性较弱；Qwen 3.6 的中文叙事很有竞争力，但默认 reasoning 延迟过高且未通过多义词消歧；Nemotron 本轮表现异常差，不适合据此选为翻译或修复模型，但本报告不推断其模型文件退化，也不否定它在历史 Remis 任务中的表现。

## 2. 测试环境

### 2.1 公共条件

- 仓库分支：`codex/3.0.7`
- Fixture：`tests/fixtures/translation_quality_benchmark_v1.json`
- Fixture SHA-256：`4fad788b58c9c48acbdb6a0d0d82563348e5e072b7dd20cfc9a45f6882a47335`
- Provider：LM Studio OpenAI-compatible API
- Remis provider temperature：`0.3`
- 每个 case 独立调用；没有并行加载多个模型
- 普通翻译复用 `BaseApiHandler._build_prompt`
- 格式修复复用 `TranslationFixerAgent._build_fix_prompt`
- 结构化解析、特殊标记恢复和游戏规则检查均复用 Remis 生产实现
- 基准进程显式清空可变的本地主词典，再按 fixture 为词典 case 注入固定条目
- 未设置人为输出 token 上限，保留当前生产 handler 的真实行为
- 所有模型均只运行一次，因此无法估计随机方差

## 3. 冻结样本

本轮包含 7 个 case：

| Case | 轨道 | 主要能力 |
| --- | --- | --- |
| `stellaris_proclamation_style` | 翻译 | 长篇政治叙事、变量、颜色标签、术语与风格 |
| `stellaris_purge_dialogue` | 翻译 | 对白、黑色幽默、嵌套引号、格式标签 |
| `victoria3_unexpected_talent` | 翻译 | 中译英、人物叙事、SCOPE 与人物变量 |
| `victoria3_daughter_of_wolf` | 翻译 | 中译英、第一/第二人称、戏剧张力 |
| `victoria3_contextual_glossary` | 翻译 | 固定术语遵循与 `silo` 多义词消歧 |
| `stellaris_missing_color_tags` | 修复 | 恢复颜色标签并保持正确条目不变 |
| `victoria3_damaged_scope_and_tag` | 修复 | 恢复 SCOPE、人物变量和颜色标签 |

词典 case 注入以下固定规则：

- `France → 法兰西`，禁止“法国”；
- `Texas → 得克萨斯`，禁止“德克萨斯”；
- `prestige goods → 名贵商品`，禁止拆词误译为“威望良好”；
- `silo → 发射井`，备注限定为军事导弹发射井；
- 农场麦仓应根据上下文拒绝该军事译名，译为“筒仓”；
- 对照文本中的 `missile silo` 必须译为“发射井”。

## 4. 自动指标

| 模型 | 总生成耗时 | API 异常 | 结构化输出失败 | 格式硬约束 | 综合质量约束 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Gemma 4 31B QAT | 273.021 秒 | 0 | 0 | 7/7 | 7/7 |
| TranslateGemma 27B | 36.181 秒 | 0 | 0 | 5/7 | 4/7 |
| Qwen 3.6 27B | 543.353 秒 | 0 | 0 | 7/7 | 6/7 |
| Nemotron Cascade 2 | 217.553 秒 | 0 | 1 | 1/7 | 1/7 |

这里必须区分三种状态：

- API 异常：连接、服务或调用抛出异常；
- 结构化输出失败：模型有返回，但无法解析成要求的字符串数组或条目数不一致；
- 格式/质量失败：得到可评估的译文，但代码格式、术语或语境判断不合格。

Nemotron 原始报告中的 `execution_failure_count = 0` 只说明 API 均返回内容；其词典 case 实际有一次结构化解析失败。本轮后运行器已新增独立的 `structured_output_failure_count`，后续 OpenRouter 报告不会再混淆这两类失败。

## 5. 语言与行为评审

### 5.1 Gemma 4 31B QAT

优点：

- 唯一完整通过词典上下文消歧的模型；
- 正确把农场 `silo` 译为“筒仓”，军事对照译为“导弹发射井”；
- 两个修复 case 均满足最终格式约束，也没有修改标记为保持不变的条目；
- 中文和英文整体可读，格式稳定。

问题：

- `a thousand` 被扩大为“数千”，存在轻微语义漂移；
- `Pax Remisia` 等无固定词典的术语有主动意译和括号加注；
- `victoria3_daughter_of_wolf` 把第一人称语境写成 `addressing him directly by name`；
- 中文对白结尾偶尔保留英文句点；
- Victoria 3 修复并非与参考译文逐字一致，主要表现为引号形式变化。

判断：本轮最均衡的默认候选。它不是每一项语言风格都最好，但在格式、词典、延迟和可读性之间没有明显短板。

### 5.2 TranslateGemma 27B Instruct

优点：

- 总耗时只有 36.181 秒，约为 Gemma 4 的 13%、Qwen 的 7%；
- 两个修复 case 最终都通过格式约束；
- 正确遵循“法兰西”“得克萨斯”“名贵商品”和军事“发射井”。

问题：

- 把农场中装满麦子的 `silo` 机械翻成“发射井”；
- Stellaris 清洗事件丢失 `§L...§!` 标签；
- 另一处 Stellaris 样本额外插入换行，严格换行一致性失败；
- 英文存在残句、引号空格和人物视角错误；
- Victoria 3 修复虽然格式通过，却明显扩写和重译，而不是只修复列出的错误。

判断：速度优势极强，适合作为未来“低成本首译 + 另一模型校对”配方的候选，但不适合在本轮结果上直接作为最高质量单模型默认值。

### 5.3 Qwen 3.6 27B

优点：

- 格式硬约束 7/7；
- 中文政治叙事和黑色幽默表现很有竞争力；
- 正确把 `a thousand` 译为“千艘”；
- 人物视角比前两个模型更合理，使用 `addressing you` 而不是 `him`；
- 变量、颜色标签和换行均稳定。

问题：

- reasoning 默认配置导致总耗时 543.353 秒，是四者中最慢；
- 同样把农场 `silo` 机械翻成“发射井”；
- 英文仍有 `a sharp, modern attire` 等语法问题和引号空格问题；
- Victoria 3 修复进行了较大幅度重译，不够克制。

判断：适合高质量候选、二次比较或 judge 实验，但当前默认 reasoning 配置不适合低延迟预览。值得以后把“默认 reasoning”和“关闭 thinking”作为两个独立配方，而不是覆盖本轮结果。

### 5.4 Nemotron Cascade 2 30B A3B

本轮观测到：

- 普通翻译大量删除或改变转义换行；
- 中英文混杂，部分术语保持英文，部分只替换句中单词；
- 词典 case 返回对象嵌套结构，无法通过 Remis 字符串数组解析；
- 农场 `silo` 在原始响应中仍被替换为“发射井”；
- 英文出现严重语法和对白边界问题；
- Victoria 3 修复把正确的 `#!` 写成 `!#`；
- 只有简单的 Stellaris 标签修复通过硬约束，且额外加入了空格。

判断：按本轮配置，不应入选翻译或格式修复配方。

但这个结论严格限定为“本轮冻结样本 + 当前 LM Studio/Remis 配置的一次运行”。开发者过去曾用同一份本地模型完成过质量没有如此异常的 mod 翻译；模型文件位于本地，不存在服务端模型版本漂移。本轮按用户要求不继续调查历史任务与当前结果差异，也不把异常简单归因为“模型退化”。可能的解释包括运行模板、thinking 行为、采样随机性、结构化输出敏感性或其他尚未核实的运行条件，均留待独立排障。

## 6. 词典系统结论

词典 case 是本轮最有区分度的样本：

| 模型 | 法兰西 | 得克萨斯 | 名贵商品 | 农场筒仓 | 军事发射井 | 总体 |
| --- | --- | --- | --- | --- | --- | --- |
| Gemma 4 | 通过 | 通过 | 通过 | 通过 | 通过 | 通过 |
| TranslateGemma | 通过 | 通过 | 通过 | 失败 | 通过 | 失败 |
| Qwen 3.6 | 通过 | 通过 | 通过 | 失败 | 通过 | 失败 |
| Nemotron | 原始响应命中 | 原始响应命中 | 原始响应命中 | 失败 | 原始响应命中 | 结构失败 |

这说明 `France/Texas/prestige goods` 适合测试“应该遵守时是否遵守”，农业与军事 `silo` 对照适合测试“是否会根据备注和上下文决定是否适用”。

同时，三个模型都在原始输出中把农场 `silo` 替换为“发射井”，只有 Gemma 4 拒绝了错误套用。当前生产词典 prompt 使用“must be translated strictly according to the glossary”这样的强制措辞，可能压过了备注中的领域限定。后续应把“模型能力”和“prompt 是否允许上下文优先”分开实验，不能只把失败归咎于模型不够聪明。

## 7. 修复模型结论

四个模型都能处理最简单的 Stellaris 缺标签样本，但复杂 Victoria 3 修复显示出明显差异：

- Gemma 4：最终格式正确，改动相对保守；
- TranslateGemma：最终格式正确，但明显扩写和重译；
- Qwen 3.6：最终格式正确，但同样进行了较大改写且非常慢；
- Nemotron：把结束标签顺序写错，修复失败。

因此，“最终格式通过”不能单独决定最佳修复模型。后续配方评分必须加入：

- 正确条目是否保持逐字不变；
- 非格式文本的编辑距离；
- 是否只修改错误报告中列出的部位；
- 修复调用耗时；
- 修复后语言风格是否被意外改变。

## 8. 当前配方建议

基于单次本地运行，暂定：

1. **综合默认候选：Gemma 4 31B QAT。**
2. **速度优先候选：TranslateGemma 27B。** 适合与廉价校对步骤组合测试。
3. **高质量/慢速候选：Qwen 3.6 27B。** 值得增加关闭 thinking 的独立配方。
4. **暂不入选：Nemotron Cascade 2。** 保留异常记录，不在本轮继续排障。

这不是产品默认配置变更。本轮没有自动修改 Remis prompt、默认 provider、默认模型或用户词典。

## 9. 限制

- 每个模型只运行一次，无法衡量随机波动；
- 只有英中、中英两个方向，不能代表 Remis 支持的全部语言；
- 没有大规模人工金标；语言评审由 Codex 辅助完成；
- 样本来自冻结 demo，不能代表大型真实 mod 的全部文本分布；
- 本地模型上下文窗口不同，虽然均足够容纳当前 case，但延迟不能视为严格硬件基准；
- 没有统计本地功耗、token 数或显存峰值；
- 当前硬约束把转义换行数量纳入严格比较，额外分段也会失败；
- 原始 JSON 报告保存在本机被 Git 忽略的 `benchmark_results/`，本报告保存汇总结论，fixture 和运行器用于复现。

## 10. OpenRouter 后续批量 benchmark

下一阶段可以复用同一 fixture 批量调用 OpenRouter 模型，但必须保持以下比较合同：

1. 固定 fixture 和源文件哈希；
2. 固定 Remis 翻译 prompt、格式 prompt、温度与词典注入内容；
3. 记录 OpenRouter 的真实 provider/model id，而不只记录展示名称；
4. 记录输入/输出 token、单次价格、总价格、延迟和失败原因；
5. 区分 API 异常、结构化输出失败、首稿格式失败和最终配方失败；
6. 对候选译文匿名化后做成对语言评审；
7. 不只比较裸模型，还要比较“翻译模型 + 校验 + 修复模型”的完整配方；
8. 对最有希望的模型至少重复运行，避免一次采样决定结论。

原始模型数量扩大后，应先用硬规则淘汰无法稳定返回结构的候选，再对剩余译文进行匿名风格比较。LLM judge 的结果仍需保存理由、置信度和无法判断项，不能伪装成人类金标。
