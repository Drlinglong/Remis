# Mod 监控开发契约

本文实现[Mod 监控产品意图](../product-intent-project-tracking.md)的代码边界。用户操作见
[Mod 监控](../user-guides/project-tracking.md)。

## 当前实现

- `ProjectWatchService` 管理监控项、手动扫描和到期扫描。
- `ProjectWatchRepository` 持久化监控项与逐文件快照。
- 扫描根只取 `localization` / `localisation`，支持 `.yml`、`.yaml`、`.csv`、`.txt`。
- 快照记录相对路径、SHA-256、大小和 `mtime_ns`；内容哈希决定修改，单独时间变化不告警。
- 无旧快照且找到文件时返回 `baseline`；没有本地化文件时返回 `no_localization`。
- 有变化时记录新增、修改、删除和 `pending_acknowledgement`，同时创建可在 Task Center
  查看详情的 `project_watch_scan` 任务。
- 定时扫描只处理启用且到期的监控项；应用退出后没有常驻进程。

## 只读边界

扫描只可读取监控目录并写监控数据库快照、摘要和 Task Center 结果。它不得写入被监控
目录、项目本地化文件、翻译归档、词典、校对结果或部署目录，也不得调用模型。

路径不可用时应保留原监控项与旧基线，并把失败作为任务和界面异常返回。不能用空快照
覆盖旧基线。

## 身份与去重

创建和修改监控项时应规范化路径并执行：

- 同一路径仅一个监控项；
- 同一非空 `project_id` 仅一个监控项；
- 冲突返回 409，并提供现有 `watch_id`；
- 未绑定项目允许保存，但增量入口不可用。

当前 `create_watch()` 只验证路径与项目存在，未执行上述重复检查，属于实现缺口。

## 变化语义

当前实现以相对路径为键。因此相同 SHA 的文件在本地化树中移动，会被报告为一项删除加
一项新增。目标实现应在路径 diff 后匹配同 SHA、同内容的增删对，把纯移动记录为非告警
信息；只有内容集合改变才进入 `changed`。

用户未确认旧告警前，后续无变化扫描不得清除 `changed`。当前服务会保留
`pending_acknowledgement`，但 UI 尚未提供完整的“已处理 / 忽略”操作。确认 action 应只
关闭本次告警，不改写磁盘快照或启动工作流。

## 调度与生命周期

- 应用启动后立即运行一次到期扫描，覆盖关闭期间错过的间隔；
- 不安装 Windows 后台服务；
- 手动与定时扫描共享项目写操作互斥键，避免读取不一致快照；
- 项目归档不得改变监控项的 `enabled`；
- 项目删除级联删除监控项及其快照。

当前项目生命周期代码会设置 `paused_by_project_archive` 并停用监控，与产品意图冲突。
应移除此联动；字段迁移时把被归档自动暂停、而非用户主动停用的监控恢复为启用。

## Agent 契约

Agent 只消费监控器的结构化结果：`watch_id`、状态、变更计数、摘要、任务 ID 和关联
`project_id`。它不能自行读取全目录后宣布“有更新”。进入增量翻译仍需用户批准，并重新
执行增量工作流自己的归档与路径预检。

## 回归门禁

1. 首次扫描只建立基线，不报告更新。
2. 非本地化文件、纯 mtime 变化和同内容目录移动不告警。
3. 本地化文件内容新增、修改、删除分别生成准确摘要。
4. 同路径或同项目重复监控返回冲突。
5. 扫描失败保留监控项与旧快照，UI/任务展示明确异常。
6. 同一告警在确认前不会被无变化扫描覆盖；确认后可关闭。
7. 项目归档不改 `enabled`；项目删除移除绑定监控。
8. 扫描不修改监控目录、不调用模型，也不自动进入增量翻译。
