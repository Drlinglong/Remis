# 封面图生成器开发契约

本文把[封面图生成器产品意图](../product-intent-thumbnail-generator.md)转换为当前实现事实、
差距和回归门禁。用户操作见[封面图生成器](../user-guides/tools-thumbnail-generator.md)。

## 当前实现

`scripts/react-ui/src/components/tools/ThumbnailGenerator.jsx` 是纯前端工具：

- 使用 512 × 512 Konva 画布；
- 支持背景色、背景图、Mod 图、自定义标识、文字和 11 种语言旗帜；
- 支持拖放、选择、移动、缩放、文字属性和删除元素；
- 非正方形背景当前按比例完整放入画布并居中，空白由背景补齐；
- 导出通过 `html2canvas` 生成 PNG，并下载为 `thumbnail.png`；
- 不调用后端、不读取项目、不写项目目录、不上传平台。

## 当前副作用

浏览器内编辑只改变组件状态。唯一外部效果是用户点击下载后触发本机下载。重置画布和
删除画布只清当前编辑状态，不删除磁盘文件。

## 输出契约

- 当前稳定输出保持 512 × 512 PNG；
- 未来可以提供更高分辨率，但预览和导出必须保持同一构图；
- 不把 WebP 宣称为 Steam Workshop 兼容格式，除非官方文档明确支持；
- 保存项目输出时使用 PNG `thumbnail.png`，并返回最终绝对目标路径。

Steamworks 通用 ISteamUGC 文档没有规定统一的 512 × 512 上限；其预览图片类型列举
PNG、JPG、GIF。因此 512 是 Remis 默认值，不是外部平台硬性事实。

## 项目集成目标

项目选择只允许：

1. 只读查找原 Mod 中的封面并载入画布；
2. 保存最新生成结果到翻译输出；
3. 覆盖翻译输出已有封面。

读取源图不等于获得源目录写权限。任何保存 API 必须由后端根据 `project_id` 解析允许的
翻译输出根，拒绝目标逃逸、源路径和任意用户路径。覆盖前先返回准确路径、是否存在、
文件大小/哈希等预览，再使用与预览一致的确认令牌执行。

项目只需保存“最新封面”的可选引用；不建立版本历史或强制每个项目都有封面。

## 非正方形输入

当前背景图只实现“完整放入并补齐”；普通 Mod 图作为元素也保持比例。产品目标还要求用户
可选择“裁剪填满”。加入时必须显式展示裁剪范围，不能改变现有补齐默认而静默切边。

## Agent 契约

Agent 可以在批准后读取项目显示信息并预填编辑器。生成在本地、保存与覆盖是分开的
action；覆盖属于需要明确目标路径的高风险 action。工具和 Agent 都没有 Workshop 上传
action，也没有源 Mod 写 action。

外部 AI 生图只能作为可选素材来源；Remis 不接收或记录用户的付费模型密钥，不在内部
静默发起付费请求。

## 当前差距与回归门禁

| 产品目标 | 当前事实 | 状态 |
|---|---|---|
| 手动上传并编辑 | 已支持 | 一致 |
| 用户选择裁剪或补齐 | 只有补齐 | 未实现 |
| 从项目自动读取原封面 | 无项目集成 | 未实现 |
| 保存/覆盖翻译输出 | 只能下载 | 未实现 |
| 保留最新项目封面 | 无项目资产引用 | 未实现 |
| 不改源 Mod、不上传平台 | 没有相关写入或上传入口 | 一致 |

必须保留或补充测试：

1. 导出固定 PNG 且尺寸与预览一致。
2. 重置、删除画布不调用文件删除 API。
3. 非正方形输入的裁剪/补齐选择与预览一致。
4. 项目取图只读；源目录任何写入均被后端拒绝。
5. 覆盖输出必须先预览准确路径，再使用匹配确认执行。
6. Agent 未获批准不能保存或覆盖，任何情况下不能上传 Workshop。
