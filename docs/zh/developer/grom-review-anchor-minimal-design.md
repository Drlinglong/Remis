# Grom 审查锚点复核与最小设计补充

Grom 首轮交付的 46 条非唯一 Lua 决定中，32 条由采集信息不完整造成，6 条需要加入控制流分支角色，8 条属于无法逐个区分的匿名重复对象。另有 18 条非文本操作应采用独立的操作类型。这是数据结构建议，尚未修改 Remis 实现或冻结的编号。

依据为 [火星本地化与 Agent 平台讨论稿](mars-localization-import-and-agent-review-proposal.md)（提交 `2b286147`）及 [46 条决定的逐项 AST 复核数据](samples/grom-anchor-gap-analysis-v1.json)。Mod 来源为 Workshop `3604444917`，原 Mod ID 为 `DoEpVdS`。

## 逻辑目标与执行位置分离

文本目标应是某对象的 Text 属性，而不是差异算法偶然选择的 String、Field 或 Table 节点。配对数组中的属性键与值共同组成一个逻辑属性；操作位置另用 property_key、property_value 等角色表达。

一次决定可以包含包装属性值、插入 Translate 等多个操作。操作仍须逐项验证，不能把整个对象的其他字段变成隐含改写权限。AST 节点类型、带序号路径、片段哈希及原偏移保留为执行和取证信息，不充当跨版本身份的必需组成部分。

## 补全机械上下文

对象属性同时识别命名字段和配对数组。身份字段按对象类明确配置，例如 EncyclopediaArticle、NotificationPreset 使用 id，ModItemOptionChoice 使用 name；不全局猜测任意字段。

字段路径保留匿名函数的属性归属，例如 NotificationPreset 的 GetObjectItem 到 ItemText。直接 Text 字段和配对 Text 属性均从实际值提取文案，不能因改写范围落在 Field 上而保存空文本。

文本与对象、字段上下文仍重复时，按需加入 control_flow_role：规范化的条件 AST，以及 then、else、elseif 角色。Grom 的六条速度提示可由此区分。条件或参数来源改变时重新审查，不能用“第几个 if”代替分支身份。

此次独立分析使用原始条件表达式验证分支区分效果。正式存储时应使用规范化 AST，以免空格和引号写法变化影响匹配；这项跨语法变化的复用能力尚未在本样例中验证。

## 匿名重复对象使用显式目标组

八个匿名按钮可表示为两个组，每个文件各四个成员。本样例中组内改写相同，可以按组审批和执行，不必制造逐个对象的跨版本身份。

组决定至少记录父作用域、逻辑属性、成员等价条件、预期数量及共同操作。成员数量改变、出现不等价成员或需要不同操作时重新审查。不得仅凭文本相同自动批准整组，也不得把旧序号当作稳定身份。若业务要求逐个维护，此案例仍应保持歧义。

## 18 条非文本操作的建模

| 类型 | 数量 | 最小记录 |
| --- | ---: | --- |
| lua_module_injection | 3 | 模块、插入阶段、声明符号、依赖证据、载荷、幂等检查。 |
| csv_transform | 1 | 表头、行身份 ID、方言规则版本、逐行源文选择及来源证据、输出规则。 |
| file_serialization | 14 | 编码、BOM、换行策略及输入输出哈希。 |

两个别名声明依赖其使用点。common.lua 的显示映射和方法钩子依赖 ChoiceList、动作 ID 集合以及原方法契约。模块 EOF 只描述位置，不能证明钩子安装时机安全；依赖变化或声明符号冲突时重新审查，并避免重复安装钩子。

CSV 作者更新后应重新定位行和 Lua 来源，沿用未受影响的解释，复核变化行，不能直接用旧整表覆盖新表。文件序列化作为明确的最后步骤执行，不伪造玩家文本主键，也不把 CRLF 到 LF 的字节变化藏进写入器默认行为。

## 最小数据结构范围

保留统一的决定外壳：理由、证据、审批状态、编号绑定、输入输出哈希。其下使用有类型的目标和操作：文本目标、显式重复目标组、模块注入、CSV 转换、文件序列化。

定位成功后仍需检查决定依赖的证据位置。此次唯一命中统计只验证原始快照中的定位，不能代替作者更新后的安全复用验证。不需要为本样例引入通用数据流分析，也不重算已经冻结的编号。

逐项数据由 diagnostics 中独立的 analyze_grom_anchor_gaps_v1.py 通过 luaparser 生成；原始快照、v1 决定库及编号台账均未修改，没有调用模型 API。运行时诊断目录保持在 Git 忽略范围内，本提交只保存设计结论和复核数据样例。
