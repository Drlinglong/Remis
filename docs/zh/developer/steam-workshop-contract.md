# Steam 工坊开发契约

本文把 [Steam 工坊产品意图](../product-intent-steam-workshop.md) 转换成 3.1.x 的实现
边界。它取代旧工坊描述技术文档中“项目必须提供 Workshop ID”和仅以时间戳文件归档
的设计；旧文档保留为 legacy 实现说明，不再作为新功能契约。

## 聚合边界

### 发布工作区

发布工作区是封面图和工坊描述的共同容器，至少具有：

- 稳定 `workspace_id`；
- 可选且可变的 `project_id`；
- 可选且可变的 `workshop_item_id`；
- 用于展示的名称和游戏上下文；
- 当前采用的封面图版本 ID；
- 当前采用的工坊描述版本 ID；
- 创建、更新时间。

项目和 Workshop ID 都是关联信息，不是工作区主键。解除关联不得改变版本主键或内容。

### 发布资产版本

版本属于工作区并具有明确 `asset_type`。3.1.x 支持：

- `cover`；
- `description`。

每个版本包含：

- 稳定 `version_id` 和工作区内递增序号；
- `asset_type`；
- `parent_version_id`；
- `status`，至少区分 `candidate`、`selected`；
- 内容 SHA-256；
- 结构化元数据；
- 创建时间和来源。

正式版本不可原地覆盖。草稿可使用独立记录或工作区级草稿槽位，但不能与不可变版本
共用含糊的更新接口。

## 内容存储

- 工坊描述正文可以存入数据库文本列；读取时必须保持 UTF-8。
- 封面图二进制存入 Remis 管理的应用数据目录，数据库只保存受控相对引用、哈希、
  MIME 和尺寸。
- 封面图的可编辑画布结构存为 JSON，并校验允许的字段和数据大小。
- 路由不得接受客户端提供的任意输出路径。
- 返回给普通 UI 和 Agent API 的是资产 ID 与受控读取入口，不是可用于任意文件读取的
  本机绝对路径。

## API 边界

建议将新能力放在独立 `/api/steam-workshop` 路由，不继续扩张 `/api/tools`：

- 列出、创建和更新发布工作区；
- 读取、保存草稿；
- 创建和列出资产版本；
- 读取单个版本；
- 选择当前采用版本；
- 生成工坊描述候选版本；
- 保存封面图候选版本。

模型生成端点必须采用“预览/批准”或等价的显式批准契约。普通保存、读取和本地渲染
不得错误地要求模型授权。

## UI 路由

- `/steam-workshop` 进入跨项目发布工作区总览；
- `/steam-workshop/:workspaceId/cover` 进入封面图编辑；
- `/steam-workshop/:workspaceId/description` 进入工坊描述编辑；
- `/steam-workshop/:workspaceId/history` 进入统一版本历史；
- 版本历史统一展示封面图和工坊描述，负责筛选、检视和明确采用，编辑器不再内嵌历史；
- 项目仪表板“更多视图”增加“发布素材管理”；
- 项目入口将 `project_id` 作为明确上下文传给共享总览并只列出该项目的工作区；
- 全局创建和编辑工作区时必须允许从已有 Remis 项目中选择绑定；
- 不复制两套编辑器或数据加载逻辑；
- “Steam 上传”“发布记录”在实现前不得显示成可执行功能。

### 工坊描述生成配置

- 工坊描述页面外层必须直接提供“API 供应商”“模型”和“描述语言”下拉菜单，以及“发布模板”文本框；
- 描述语言下拉菜单必须复用 Remis `/api/config` 返回的 11 种语言事实来源，不得在前端复制另一份会漂移的语言列表；
- 用户先在页面外层完成供应商、模型、11 种语言之一和模板配置，再点击“模型生成”；
- 确认弹窗只展示本次调用摘要并要求用户明确批准，不得把供应商、模型、描述语言或模板输入重新藏入弹窗；
- 工坊描述生成页面和确认弹窗均不显示并发数或 RPM 设置。

## 任务中心契约

- 保存封面图时先创建 `steam_workshop_cover` 任务；PNG 与可编辑画布版本都持久化成功后才标记完成，否则标记失败；
- 调用模型生成工坊描述前创建 `steam_workshop_description_generation` 任务，并记录读取公开工坊内容、模型生成、保存候选版本三个阶段；
- 工坊描述是一次 API 调用，终态只有完成或失败，不使用“部分成功”；
- 手动保存描述候选不创建后台任务，避免用普通编辑操作污染任务中心；
- 任务必须持久化到统一任务仓库，并通过 `source_route` 返回产生任务的工作区资产页面。

## 旧实现迁移

- `WorkshopGenerator.jsx` 不再读取不存在的 `project.workshop_id`；
- `archive_generated_description()` 不再作为新版本系统的事实来源；
- 能可靠识别项目的旧 Markdown 归档可以提供显式导入，不做静默批量迁移；
- 旧封面图生成器的下载能力可保留，但下载不等于保存版本；
- 重构现有超过责任阈值的封面图组件时，画布状态、持久化和页面呈现必须拆分。

## 3.2.x 预留

未来发布记录应引用精确的工作区、封面图版本和工坊描述版本，形成不可变发布清单。
上传成功后才能写入远端 Workshop ID 和发布结果。上传失败不得把候选版本标记为已发布。

## 验证要求

- 数据库升级和从旧版本启动测试；
- 工作区 CRUD、可选关联和版本不可变测试；
- 受控文件引用与路径穿越测试；
- 前端项目上下文与全局上下文测试；
- 草稿恢复、保存版本、选择版本测试；
- 模型调用批准和失败后不产生虚假版本测试；
- UTF-8、BBCode 原样往返和封面图哈希测试；
- 前端 lint、构建、组件行数及责任边界检查。
