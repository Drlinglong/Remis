# Project Zomboid adapter: source and format evidence

**Purpose.** Evidence for an offline-first Remis adapter. This note describes file formats and a conservative implementation boundary; it does not claim live-game verification. No vanilla translation corpus is copied here. The user has no game installation available, so fixtures and GUI checks must be synthetic or permissioned and in-game compatibility must remain unverified.

## Evidence and pinned references

- The Indie Stone's official **42.15.0 UNSTABLE** announcement (9 March 2026) says “Localization clean-up. Translation files are now in json”; it also records fixes to COMMON/VERSION mod-folder detection, translation loading order, and translation support for mod.info title and description: [official announcement](https://theindiestone.com/forums/topic/92435-42150-unstable-released/). This pins the migration evidence to 42.15.0 unstable; it is not a minimum-version gate. Keep legacy support and probe each mod's actual files instead of rejecting game builds by version string.
- File-specific JSON shapes and conventions are corroborated by the community-maintained [PZ Translation JSON Schema](https://github.com/escapepz/pz_translation_json_schema), observed remote main at commit 3bd67aa222b4d962aa0708d5b8df2e9e38caa28f on 2026-09-25. Its README says it covers files under media/lua/shared/Translate/, gives examples such as ItemName.json with string key/value pairs, and describes 30 modular schemas for 35 file categories. The repository declares MIT for its schema project, but explicitly says its media/lua/shared/Translate/EN data is vanilla Project Zomboid content, all rights reserved by The Indie Stone. Reuse schema concepts/links only; do not copy those data files into Remis.
- As a practical compatibility cross-check, [ppebble/pz-ai-translation-generator](https://github.com/ppebble/pz-ai-translation-generator) was observed at remote main commit afc0ac49baead83d5442d07b8a9cb10ffab9b13b on 2026-09-25. Its README describes B42 Translate/EN JSON and legacy Lua-table TXT such as IG_UI_EN.txt and Recipes_EN.txt, and explicitly distinguishes resource-backed strings from hard-coded Lua literals. This is implementation evidence, not an official spec.
- Version-folder selection details are corroborated by the community [PZ Modding Toolkit guide](https://github.com/drandarov-io/project-zomboid-mod-toolkit/blob/master/MODDING.md), observed 2026-09-25: common loads first, then the closest compatible build/version folder overrides it; a folder such as 42.1.5 behaves as 42.1. This is secondary evidence; official 42.15 notes confirm the engine fixed COMMON/VERSION detection and load order but do not publish the full comparison algorithm. The adapter chooses the greatest applicable build.major tuple and ignores a folder's third component.

## Format and discovery findings

- Translation resources live beneath a mod's media/lua/shared/Translate/<language>/. JSON category files use a JSON object with localization keys mapped to text values in the common case; key names are identifiers and must never be translated. Treat unknown category shapes, non-string values, malformed files, and duplicate keys as parse/review errors rather than guessing.
- Before 42.15, common mod files use category names with language suffixes (for example UI_EN.txt, IG_UI_EN.txt, Recipes_EN.txt). These are Lua-table-shaped data, not scripts to run. A safe parser accepts only a deliberately small grammar of table constructors, literal string keys, and literal quoted string values; it rejects expressions, concatenation, calls, computed keys, metatables, or unsupported syntax with a file-scoped diagnostic. Never execute mod Lua. The writer changes value spans only and preserves comments, whitespace, quote style, line endings, and encoding when possible; malformed/ambiguous source is read-only.
- Search a selected mod root and only its standard media/lua/shared/Translate tree; recognize one unambiguous mod inside standard Workshop Contents/mods or mods containers. Never follow symlinks/junctions or recursively mix unrelated historical folders. Resolve effective candidates using an explicit game-version input when available; keep common resources as fallback. If version is unknown, choose the locally newest build.major branch and report that inference. Do not impose a version threshold that excludes otherwise parseable files.
- Language folder and legacy filename suffix must agree. Treat folder names actually present (for example EN) as authoritative identifiers; do not infer language solely from filename text or hard-code an incomplete language allowlist. Target output belongs in the matching target-language directory and preserves category filename/layout, updating the language suffix on legacy TXT names. The 42.15 mod.info title/description localization is a separate supported resource shape; this adapter emits its own deterministic overlay mod.info identity and handles translated metadata only if exposed through supported translation resources.
- Translate values only. Preserve key identity, Lua/JSON syntax, PZ runtime placeholders/substitution tokens (including numbered %n forms where present), markup/control tags, and escaped line breaks. Compare token identities and multiplicity on output. Do not convert semantic tokens into generic placeholders before any model call. Strings directly embedded in Lua are outside a resource-file adapter and must not be reported as covered.

## Proposed adapter contract

1. Identify JSON files under the translation directory and legacy files matching <Category>_<LANG>.txt without executing source.
2. Return entries with stable category-plus-resource-key identity, independent of absolute path, source language, or version branch. A key is opaque and protected; only values are eligible. Reject duplicate JSON keys as a blocking parse error.
3. Preserve source bytes/encoding and all non-value syntax on translation writeback. For JSON, edit only string value tokens and retain source ordering/whitespace; for TXT, use a bounded lexical parser plus source spans. Refuse unsafe/ambiguous rewrites.
4. Discover common and version-scoped resources independently; choose the effective branch deterministically from the supplied game version and report the selected path. Report unresolved conflicts rather than overwriting.
5. Build a deterministic generated overlay identity from the source mod's declared ID, require that original ID as a dependency, and select root/common layout from local files even when game version is unknown.
6. Validate JSON syntax / safe TXT parse, key stability, placeholder/tag identity, target-language path and legacy table language suffix, and round-trip output. Deterministic token mismatches are blocking errors. Diagnostics should distinguish unsupported syntax, inferred version resolution, and hard-coded Lua text outside scope.

**Validation boundary:** synthetic fixtures can establish parser behavior, safe writeback, discovery and GUI surfacing. Without the game, do not claim runtime load or in-game behavior verified.
