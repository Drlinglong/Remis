# 火星 Lua 文本国际化工作流

状态：2026-09-25。已实现只读 Lua 扫描、静态身份清单、标准 CSV 准备，以及有批准 ID 和源哈希保护的 Lua 改写预览原语，见 `scripts/core/mars_pipeline/`。
FLPK 有界文本探测在当前样例上取得 22/22 Lua 字节一致结果。产品级 Agent 审批、作业状态和两种交付方式应以对应 API 的持久化结果为准；仅调用准备函数不代表翻译、打包或游戏运行验收完成。

## 目标与分层

代码国际化只做一次，语言翻译可以重复进行。Lua 引用稳定 ID 和英文回退，中文、日文等译文进入各语言 CSV。
现有 CSV 项目、按条目增量更新、标签/换行校验和翻译存档继续复用，不再建立绕过 Remis 的脚本翻译通道。
不修改 Steam 缓存，不恢复会与 Steam 原 Mod 冲突的可编辑 Mod 安装，不执行输入 Mod 的 Lua 来发现文本。

处理顺序：压缩包识别/隔离解包 → 源快照 → 覆盖扫描 → 候选复核 → 身份清单 → 国际化改造预览 → CSV 翻译项目 → 校验 → 按交付方式导出 → 游戏验收。

## 0. 从 Mod 压缩包开始

用户只需选择原始 Mod 包或源目录。包适配器按文件签名识别格式，不按后缀猜测；解包到 Remis 数据目录中的独立快照，不向游戏的 Mods 或 Workshop 缓存写入。
固定记录包 SHA-256、工具来源/版本、格式版本、文件清单、每文件大小/哈希及失败原因。路径穿越、绝对路径、重复/大小写冲突、链接、异常数量/展开体积和未知压缩方式必须拒绝。
包内 Lua 始终作为数据读取，不在 Remis 进程里执行。解包、Lua 字节码反编译和文本提取是不同能力；拿到脚本文件不等于拿到可读源码。
社区旧工具的实际兼容测试记录在[解包器探测记录](mars-unpack-probe.md)；不得把 HPK 支持宣传为 Relaunched FPK 支持。

解包成功后优先读取已有 CSV；没有 CSV 时需要额外的文本提取阶段。静态 `T(ID, 英文)`、可识别的 ModItem 属性、继承默认值和硬编码候选分别报告来源。
官方 `GedOpGenTTableMod` 通过 `ModItem:GenTTable()` 遍历游戏实例的属性，不能用正则寻找 `T` 就声称完全等价。
当前样例的静态字面 `T` 探测可匹配官方 49 条中的 46 条；余下 3 条来自 SDK 的 StoryBit/Condition 默认属性。此外发现 4 个不在该 CSV 中的 `T` ID，其中含游戏共用文本。
因此不能盲目重译并覆盖这些共用 ID，也不能把未解释的继承项静默丢弃。正式提取器需要属性/继承规则与来源区分，并用已知官方 CSV 进行独立对照。
共享游戏默认文本应记录为游戏提供的依赖，优先复用游戏自己的本地化；除非确认 Mod 特意覆盖该语义，不为补齐数量而重译全局 ID。
目标是消除日常手工导出步骤；不支持的包版本或脚本形态仍必须给出明确诊断，而不是自动执行任意 Mod 代码补齐结果。

## 1. 发现和分类

通过既有 `projects/inspect` 或 `projects/{project_id}/game-support` 获取 `hardcoded_lua`。
CSV 条目数仍只统计真正可翻译的 CSV。硬编码候选单列，不能加入完成率分母后假装已经翻译。
实现发现直接调用的 `Untranslated`：普通引号、长括号字符串、注释、转义字符由词法扫描处理；不使用全文正则替换。可证实的字符串常量拼接、`string.format` 和字面表调用也会提取模板并保留命名参数。

- 单一字面量：展示源文件、行号、完整调用范围、英文文本和调用/源文件哈希；可进入人工审核。
- 无法安全折叠的拼接、格式参数或表表达式：标为动态候选，保留在复核清单；不得执行表达式。
- `ModItemOptionChoice` 的 `DisplayName` 和 `Help` 字符串会单独列入人工审核；`ChoiceList` 值是内部枚举，不翻译。符合文案命名的 Lua 字符串别名也会报告供复核。
- 任意别名调用、反射和运行时生成文本仍有覆盖盲区，扫描结果必须保留覆盖诊断。
- 无法解码、词法错误或预算耗尽：报告部分扫描，不能把失败文件当成没有遗漏。

候选不是自动修改许可。日志、内部标识、文件路径与用户可见文本必须区分。
内置 Agent 接收计数和覆盖边界；Codex 可通过只读 Agent API 检查具体候选。两者均不得把 CSV 成功解释为整 Mod 完成。

## 2. 持久化身份清单

审核后的清单至少包含 `schema_version`、源 Mod ID、语义身份、数字本地化 ID、原文、来源定位、参数契约、处置决定及依据。
另存快照版本、所有源文件哈希、调用哈希和定位范围；这些是重放条件，不是长期身份。

当前语义锚点由 Mod ID、Lua 文件角色、函数范围和赋值字段组成；Mod Options 使用选项 `name` 和字段名。已有清单会按语义锚点沿用 ID，因此改英文、移动同名源文件或调整候选顺序不会重建身份。
无法唯一匹配或同一锚点出现多个不同原文时，保留复核状态，不假称身份已稳定。已有数字 `T` ID 原样复用；新增 ID 在 900000000000–999999999999 范围分配并避开已知引用。
官方资料要求完整保留 CSV ID，但没有给出数字上限；12 位范围与官方源码中可见的现有 ID 位数一致，不代表已证明游戏的最大值。
无法唯一匹配时保留候选并要求复核，不覆盖旧译文。删除保留 tombstone，已有 ID 不回收给其他条目。

## 3. 代码改造与翻译输入分离

明确可改造的字面量将 `Untranslated("English")` 改为 `T(稳定数字ID, "English")`；运行时参数使用 `T{ID, "模板", name = expression}`，保留原计算和命名参数。已有 `T(ID, English)` 调用不改写。
所有语言共用这一份代码和 ID；没有译文时保留英文回退，不把中文写进 Lua，也不根据当前目标语言生成不同代码。
真正的多语言运行时切换行为仍需按游戏机制验证，不能把 `T` 包进 `Untranslated` 再丢掉本地化能力。

模板改造只接受静态字符串和明确的运行时绑定；`string.format` 的宽度、精度和转义百分号通过运行时参数保留。不能对拼接碎片逐段翻译，不能改变数值计算、游戏逻辑或标签参数。
未支持的动态项会成为源副本交付阻断项；交付报告必须列出它们，不能标为整个 Mod 已完成。

改造执行必须验证源快照和每个调用哈希，按词法范围生成精确差异；预览后源变化即失效。
只在隔离输出目录生成修改文件及清单，源目录保持只读。重复运行使用相同清单，不能重复包裹 `T`。

从批准清单产生标准 `ID,Text,Translation,VoiceActor,Context` CSV，英文放 `Text`，初始 `Translation` 为空。
`Context` 提供来源、用途和参数说明。导入新的受管项目或按明确的项目资源更新机制登记；不能仅往已导入源目录塞文件后假定数据库自动同步。
使用用户指定的供应商、模型和语言，通过现有 Remis 计划/审批/作业 API 翻译；不擅自开启词典、校对或高级存档功能。
新增候选量和费用需重新展示；之前 49 条文本的调用授权不能无限扩张为任意新文件的付费翻译。

## 4. 用户准备与交付模式

用户在“创建项目”选择 Surviving Mars 后进入单独的 FPK 准备说明/检查窗口。准备计划字段 `delivery_mode` 默认 `source_copy`：`text_only` 生成 CSV 而不改写 Lua，且原 Mod 是必需依赖；`source_copy` 包含全部资产并仅改写已审核且可安全渲染的文本。等待人工复核的候选在 `text_only` 下不进入翻译 CSV，在 `source_copy` 下不能被假装已改写。候选数只描述扫描结果，不证明整 Mod 覆盖完整。

准备完成后，日常导出 UI 的两个选项为完整源副本和只含文本的翻译包。运行时 `overlay` 仅为高级 API 模式，只有存在已审核且无阻断项的运行时绑定配置时才可选用；不作为普通用户推荐。完整源副本生成新的 Mod ID，并给标题添加 `[Remis i18n]` 前缀；会替代原 Mod，必须停用原 Mod。存档迁移和运行时加载仍需在游戏中验证。

| 方式 | 前提 | 文件与安装关系 |
| --- | --- | --- |
| 完整国际化源副本（`source_copy`） | 硬编码文本需由可审查的源码调用提供稳定 ID | 输出完整资产副本、审核过的 Lua 改写和各语言 CSV；生成新的 Mod ID 与 `[Remis i18n]` 标题；停用原 Mod，保存兼容性待游戏验收。 |
| 只含文本的翻译包（`text_only`） | 原 Mod 已有可用 CSV，或暂时不处理硬编码 Lua | 只输出已纳入 CSV 的翻译表，依赖原 Mod；不改 Lua，不覆盖硬编码 `Untranslated` 文案。 |
| 运行时覆盖（`overlay`，高级 API） | 经验证的对象/属性绑定、加载时机和刷新行为 | 保留原 Mod 并附加按语言加载的 CSV；只有完整审核绑定配置且无阻断时允许导出。 |

完整源副本共享一套国际化代码，各语言使用独立 CSV；文本包只携带语言 CSV，不含源 Mod 资产。输出完整副本时原始图像按字节复制，不能称作仅含译文的小包。
每次准备需保存模式、批准 ID 快照、文件/调用哈希、代码差异、资产清单、依赖和阻断项；源文件变化后必须重新分析。

## 5. 增量、失败与验收

源快照变化时先重新扫描并匹配清单，再比较每条英文与参数契约；Mod 元数据版本变化不触发全量重译。
代码锚点失配、多个候选、ID 碰撞、未知动态表达式均停止该条目的自动处理，保留其余有效候选。
持久化准备结果、翻译作业和导出清单各有状态，避免“扫描成功”被报告为“可安装”。

自动检查：词法边界/转义、稳定键迁移与碰撞、字节级源只读、重放幂等性、过期快照、标准 CSV 解析、全部 ID 对应、标签/参数/真实换行、修改范围及原游戏逻辑不变。
独立于读写器的固定预期样例用于验证生成文件；不以自写自读代替正确性证据。
运行验收：英文回退、至少两个目标语言、新游戏/旧存档、升级未建/已建、科技解锁、Mod 设置变动、选择不同建筑、重新加载及原 Mod 更新后行为。
任何未执行的游戏检查都保留为待验证，API 仍返回 `runtime_verified: false`。

## 当前 Mod 的证据

Exotic Minerals Expanded 的 `Code/Exotics_AccumulatorUpgrade.lua` 在 `ApplyUpgradeFields` 中以 `Untranslated` 写入升级名称与说明，且存在 ClassesPostprocess、LoadGame、PostLoadGame、GameTimeStart 等路径。
其他升级脚本也有自己的初始化/刷新逻辑。因此仅启动时覆写一次显示属性不是已证实可靠的解决方案。
优先研究这八类升级的稳定 upgrade ID 和实际属性读取路径；不要改动 upgrade ID、科技 ID、资源成本、效果计算或存档字段。
科技和事件 CSV 已翻译并由用户确认加载有效，这项证据不覆盖尚未处理的 Lua 文本。

2026-09-25 对 Exotic Minerals Expanded 的准备扫描读取 22 个 Lua 文件：找到 47 条现有数字 `T` 文案、25 个 `Untranslated` 调用（12 个字面量、11 个可参数化拼接/格式模板、2 个表模板），以及 16 个需人工批准的 Mod Options `DisplayName`/`Help` 文案。三个 SDK 共用数字 ID 单独列出，不进入待翻译条目。这些是该归档快照的候选计数，并非整 Mod 覆盖证明；普通静态扫描仍可能漏掉别名、继承字段和运行时文本。
当前源副本改写只接受经批准的 ID，逐文件与逐调用校验 SHA-256；无法改写的动态表达式会阻断源副本完成状态。这个静态检查不等于游戏内运行验收。
