# 部署工作流开发契约

本文把[部署产品意图](../product-intent-deployment.md)转换成开发边界，并区分：

- 3.1.0 已经实现的行为；
- 产品已经确认但尚未实现的目标行为；
- 仍需产品负责人与 Agent 共同确认的规则。

它不是面向普通用户的操作教程。操作步骤见
[一键部署](../user-guides/one-click-deploy.md)。

## 范围

包含：

- 翻译结果页和项目概要中的部署入口；
- 部署预览、批准和覆盖确认；
- Remis 输出到 Paradox 用户 `mod` 目录的复制；
- 启动器描述文件写入；
- 部署任务和项目历史；
- 与假本地化清理之间的授权隔离；
- 成功、警告和失败语义。

不包含：

- 翻译主流程如何生成输出；
- 启动器播放列表或加载顺序自动化；
- 游戏内实际效果验证；
- 假本地化删除算法的完整设计。

## 当前公共入口

### 前端

- `TaskRunner.jsx`
  - 初次翻译任务为 `completed` 或 `partial_failed` 时显示结果区；
  - 结果区包含“一键部署”和“删除假本地化文件”入口。
- `ProjectHeader.jsx`
  - 活跃项目可从主动作、辅助动作或项目菜单进入部署；
  - 只要项目存在已完成文件或归档语言，就可能被识别为已有可部署翻译；
  - 项目存在验证问题时，当前界面优先引导修复格式。
- `useDeployActions.js`
  - 获取部署预览；
  - 持有覆盖确认状态；
  - 提交明确批准的部署；
  - 独立处理假本地化清理。
- `DeployModals.jsx`
  - 展示只读目标路径、源输出和覆盖告警；
  - 存在验证错误时禁用部署；
  - 同名目标存在时要求勾选覆盖确认；
  - 清理假本地化使用独立的红色二次确认弹窗。

### 后端

- `POST /api/tools/deploy_preview`
  - 校验项目、输出和目标；
  - 返回源路径、目标路径、目标是否存在、验证错误数；
  - 创建十分钟有效的单次部署预览。
- `POST /api/tools/deploy_mod`
  - 要求 `approved=true`；
  - 要求预览仍然存在且与请求一致；
  - 目标已存在时要求独立覆盖确认；
  - 拒绝把假本地化清理藏进部署批准；
  - 创建可追踪的部署任务并记录结果。
- `POST /api/tools/deploy_info`
  - 返回默认部署位置和清理假本地化所需的原始 Mod 信息。
- `POST /api/tools/clean_fake_loc`
  - 独立执行假本地化清理。

## 当前路径信任边界

### 源目录

`ModDeployer._resolve_output_source()` 只接受 `DEST_DIR` 下真实存在的直接子目录，并按
精确目录名查找。调用方不能通过路径拼接把任意文件夹伪装成 Remis 输出。

### 目标目录

`ModDeployer.resolve_deploy_target()` 根据游戏 ID 选择：

```text
Documents/
└── Paradox Interactive/
    └── <Game>/
        └── mod/
            └── <Remis output folder>/
```

Windows 下会先检查标准 `Documents`，再检查 OneDrive `Documents`。目标目录不存在时，
当前实现会尝试创建。

即使请求带有 `target_deploy_path`，它也必须与检测得到的目标完全相同。当前实现不支持
把输出部署到任意自定义目录。

### 原始 Mod

直接部署不读取或修改创意工坊目录。只有独立的假本地化清理需要原始 Mod 路径。

## 当前部署事务

### 预览阶段

预览记录：

- 项目 ID；
- 输出文件夹名；
- 游戏 ID；
- 实际源输出路径；
- 实际目标路径；
- 目标是否已存在；
- 项目格式验证错误数；
- 创建时间。

预览十分钟后失效，且成功进入执行阶段时只能消费一次。项目、源、目标或目标存在状态
发生变化后，旧预览不得继续使用。

### 执行阶段

当前 `ModDeployer.deploy_mod()`：

1. 再次解析可信源目录和可信目标；
2. 如果目标目录已经存在，先递归删除整个同名目标；
3. 把 Remis 输出完整复制到目标；
4. 对需要 `descriptor.mod` 的游戏更新其中的 `path`；
5. 在 Paradox `mod` 根目录写入 `<output_folder_name>.mod`；
6. 返回目标文件夹及描述文件路径。

Victoria 3 在没有 `descriptor.mod` 时可以只复制目标文件夹并返回成功。
其它游戏缺少描述文件时，当前实现返回 `warning`，提示启动器可能无法识别。

### 重要的当前限制

覆盖不是原子事务。当前实现先删除旧目标，再复制新目标；如果复制中途失败，没有自动
回滚旧部署的保证。产品意图要求覆盖前明确确认，但目前没有要求 3.1.x 重写为原子替换。
因此界面和文档不得承诺“失败时旧部署一定安全”。

## 当前任务与错误语义

部署是用户显式创建的阻塞任务：

- `kind="deployment"`；
- `created_by={"type": "user"}`；
- 同一项目的冲突写任务会被拒绝；
- 成功时记录实际输出路径、预览 ID、目标和是否替换；
- 项目存在时尝试写入 `deployment_completed` 历史事件。

底层返回：

- `success`：目标复制完成，所需描述文件已处理；
- `warning`：文件已复制，但启动器描述文件可能缺失；
- `error`：部署未完成。

异常和底层错误在公开响应中统一为安全错误文案，具体本机路径留在诊断日志中，避免
把敏感路径直接暴露到任务摘要。

## 当前确认契约

部署必须依次满足：

1. 新鲜预览存在；
2. 用户明确批准部署；
3. 预览与执行请求一致；
4. 源和目标未发生变化；
5. 当前没有验证错误；
6. 目标存在时用户明确确认覆盖；
7. 没有夹带假本地化清理。

覆盖确认是部署批准之外的独立布尔值。前端在目标存在时禁用执行按钮，后端也再次检查。

假本地化清理在前端使用独立弹窗和第二次确认。部署路由明确拒绝
`clean_fake_loc=true` 或携带 `workshop_path` 的请求。

## 已确认的目标契约

### 可部署资格

部署入口面向“已有可用翻译成果”的项目：

- 完全成功：允许部署；
- 部分成功且存在可玩输出：允许部署；
- 百分之百失败或没有输出：不允许执行部署。

校对不是硬性前置条件。项目概要中的可部署资格不能只用“翻译是否达到 100%”判断。

### 部分成果确认

预览必须能够表达当前输出是否含原文回退。存在回退时：

- 展示醒目的非技术警告；
- 明确仍可进入游戏，但部分内容会保持源语言；
- 要求独立确认；
- 将该确认与预览绑定，不能复用到后来变化的输出；
- 不修改数据库失败条目和基线状态。

推荐新增结构化字段，而不是从日志文案推断：

```text
contains_source_fallback: boolean
failed_scope_count: integer | null
failed_scope_unit: batch | file | entry | unknown
requires_partial_output_confirmation: boolean
```

报告单位可以沿用现有批次或文件口径，不要求为了部署重构翻译后端。

### 用户可理解的结果

成功结果至少说明：

- 文件已部署；
- 实际目标位置；
- 是否替换了同名旧部署；
- 下一步是打开启动器、加入播放列表并调整加载顺序。

警告结果必须说明文件是否已复制以及启动器识别可能有什么问题。

失败结果至少说明：

- 部署没有完整完成；
- 可以重新生成预览并重试；
- 诊断入口；
- 如果系统不能证明旧部署仍可用，就不得声称旧部署安全。

## 与启动器的边界

部署工作流不得：

- 启动 Paradox Launcher；
- 修改播放列表；
- 添加或启用 Mod；
- 调整加载顺序；
- 自动启动游戏；
- 把“文件复制成功”提升为“游戏内翻译已生效”。

用户指南和 Copilot 回答必须把这些步骤交还给用户。

## 与清理和元数据的边界

- 部署批准不授权修改原始 Mod 或创意工坊文件。
- 清理假本地化必须保持独立入口和二次确认。
- 部署不能自动删除旧部署；只有同名覆盖并经过独立确认时，才可替换该项目目标。
- 部署不能自动清理 Remis 项目元数据或其它无关文件。
- 为启动器识别而生成或更新项目自己的 `.mod` 描述文件属于部署本身，不等于清理元数据。

## [共同确认] 当前验证阻止规则

当前预览把所有 `severity="error"` 的验证问题视为硬阻止，前端禁用按钮，后端也拒绝。

产品决定同时要求：只要存在非百分之百失败的可用输出，就应该提示用户可以部署。
实现前必须共同确认验证问题的分级：

- 会导致游戏无法读取或明显破坏输出的错误：可以继续硬阻止；
- 仅表示翻译不完整或质量不足的问题：应警告并允许用户确认后部署；
- 尚不能判定的错误：默认策略由产品负责人决定。

在该决策完成前保留现有硬阻止行为，不通过文档更新偷偷改变运行规则。

## 与产品意图的当前差距

| 产品意图 | 3.1.0 当前行为 | 状态 |
|---|---|---|
| 部分成果部署前显示“仍有原文”并再次确认 | 预览没有原文回退字段或确认 | 待实现 |
| 百分之百失败不提供可执行部署 | 依赖是否存在输出目录，缺少明确资格字段 | 待核验/补契约 |
| 部署成功后说明启动器下一步 | 成功通知较简短，用户指南有说明 | 可改进 |
| 原始 Mod 更新给出软提示 | 当前部署预览未比较源版本时间 | 未来维护项 |
| 区分硬阻止验证错误与软警告 | 当前所有验证错误均硬阻止 | 共同确认 |
| 能判断跨用户稳定性和静默失败 | 有任务记录，缺少已证明的产品级成功率证据 | 观测不足 |

## 测试契约

### 已有覆盖

- 拒绝 `DEST_DIR` 外或路径穿越形式的输出；
- 目标限制在检测到的 Paradox 用户 `mod` 目录；
- 同名目标替换及不同游戏描述文件处理；
- 新鲜预览、显式批准和单次消费；
- 预览不匹配或过期后拒绝；
- 验证错误阻止部署；
- 同名目标需要独立覆盖确认；
- 部署批准不能夹带假本地化清理；
- 成功部署进入任务结果和项目历史；
- 公开失败结果不泄露内部路径；
- 清理只删除非源语言内容并拒绝非 Mod 目录；
- 前端覆盖复选框和清理二次确认。

### 后续必须补充

1. 部分成果预览返回结构化原文回退状态。
2. 部分成果未经额外确认时拒绝部署。
3. 部分成果确认后允许部署，且不改变数据库或基线。
4. 百分之百失败或无可用输出时拒绝部署。
5. 部署结果明确给出启动器下一步但不宣称游戏内成功。
6. 若以后改变验证规则，分别覆盖硬阻止与软警告。
7. 清理接口若开放给 UI 以外的调用方，必须保留等价的服务端明确授权契约。
