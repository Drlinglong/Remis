# 词典与词汇表：怎么用

> 侧栏入口：**「词汇表管理」**。  
> 词典用来规定 **游戏术语的标准译法**（如专有名词），让 AI 翻译时前后一致，减少「同一英文三种中文」的情况。

面向 **打包客户端用户**。开发向的 JSON 结构、parser 脚本等见 `docs/zh/glossary/`（一般玩家不必读）。

---

## 1. 词典是干什么的？

翻译时，Remis 会把相关词条提示给模型，例如：

| 原文术语 | 希望统一成 |
|----------|------------|
| convoy | 船队 |
| Prestige | 威望 |

**有词典**：同一术语在不同文件里更一致。  
**没词典**：模型可能每次自由发挥，后期校对成本高。

词典 **不替代** 人工校对，也不负责修 `$变量$` 格式问题（格式见 [错误目录](error-catalog.md)、[智能工坊](agent-workshop.md)）。

---

## 2. 三种常见词典

| 类型 | 是什么 | 典型用途 |
|------|--------|----------|
| **主词典** | 某游戏自带的主术语库 | Vic3 / Stellaris 等通用官方/社区术语 |
| **额外词典**（外挂） | 同一游戏下的其它词典文件 | 主题包、系列 Mod、你自己维护的扩展词表 |
| **项目词典** | 绑定到 **某一个汉化项目** | 该 Mod 专有人名、地名、势力名；新词挖掘常会往这里写 |

界面里：

- 维护全局/按游戏的词表 → 侧栏 **词汇表管理**  
- 看/绑项目专属词典 → **项目管理** 里该项目的 **「项目词典」** 页签  

---

## 3. 词汇表管理：日常怎么操作

### 3.1 打开与选择

1. 左侧 **「词汇表管理」**。  
2. 选 **游戏**。  
3. 选 **目标语言**（列表里「译文」列按此语言显示）。  
4. 在左侧 **词典文件** 树中点开一本词典（主词典或其它 `.json` 文件）。  

未选文件时，右侧会提示先从左侧选择。

### 3.2 增删改词条

| 操作 | 做法 |
|------|------|
| **新增词条** | 选中词典后点 **「新增词条」**，填源文本、译文、备注等 |
| **编辑** | 在表格中打开编辑（含备注查看/编辑） |
| **过滤** | 用过滤框缩小列表 |
| **删除词条** | 单条删除（需确认） |
| **删除整本词典** | **「删除词典」**——会删掉该文件内全部词条，**不可撤销**，慎用 |

常见字段：

| 字段 | 含义 |
|------|------|
| **源文本** | 原文术语（如英文） |
| **译文** | 目标语言译法 |
| **备注** | 给自己看的说明（语境、出处） |
| **变体** | 同一术语的其它写法（复数、拼写变体等；界面提示可用逗号分隔） |

高级模式（若开启）可能还有缩写、元数据等 JSON 字段；日常维护源文本 + 译文 + 备注即可。

### 3.3 创建新词典文件

1. 先选好 **游戏**。  
2. 点词典文件旁的 **创建**（+）。  
3. 输入文件名，需为有效 **`.json`** 名（如 `my_mod_terms.json`）。  

新建后可在翻译时作为 **额外词典** 勾选，或绑定为项目词典（见下）。

---

## 4. 翻译时如何启用词典

在 **初次翻译** / **增量翻译** 的配置步骤中（界面文案以版本为准）：

| 选项 | 作用 |
|------|------|
| **使用主词典** | 自动带上该游戏的主要词典（一般建议保持开启） |
| **额外词典** | 再勾选一本或多本扩展词典 |

**建议：**

1. 通用术语靠 **主词典**。  
2. 系列/主题术语放 **额外词典**，翻译时勾上。  
3. 单个 Mod 专有名词用 **项目词典**（项目管理中绑定），避免污染全局主词典。  

只改词典、不重新翻译，**已经生成的旧译文不会自动变**；需要的话对相关内容再译、校对，或增量更新时再依赖新词表。

---

## 5. 项目词典（项目管理）

在 **项目管理** 打开某个项目 → **「项目词典」** 相关区域：

- 说明大意：新词挖掘等流程生成的 **Mod 词典** 会与当前项目绑定，保证专有名词一致。  
- 可能看到：当前是否已绑定、**创建并绑定项目词典**、**绑定词典**、**解除绑定**、**检查词典术语**。  
- 新词挖掘开始时，Remis 常会 **自动** 为项目准备/绑定项目词典。  

**主词典重复** 类提示：候选词已在主词典或相关词典中——可沿用已有译法，或坚持建项目专属义项（按界面警告选择）。

## 6. 什么词值得进词典？

| 建议收录 | 通常不必硬塞 |
|----------|----------------|
| 反复出现的游戏机制名 | 只出现一次的普通句子 |
| 专有人名、地名、组织名 | 已由主词典覆盖且译法正确的词 |
| 社区已有统一译法的术语 | 会破坏格式的「伪术语」（变量、脚本 key） |
| 本 Mod 独创设定名 | 纯口语连接词 |

**不要** 把 `$COUNTRY_NAME$`、`[Concept('...')]` 一类 **脚本标识** 当术语翻进词典当中文 key——那会害翻译弄坏格式。

收录原则的更细讨论见：`docs/zh/glossary/inclusion_principles.md`（偏规范，可选读）。

## 7. 推荐工作流

```text
开始新项目前
  → 确认主词典已启用
  → 有主题词表则准备额外词典

翻译中 / 译后
  → 发现译名乱：在词汇表管理补词条
  → 再译相关批次，或校对统一旧句

Mod 专有名词多
  → 用项目词典；可配合新词相关功能（若版本开启）

进游戏前
  → 术语问题主要靠词典+校对
  → 格式问题走智能工坊
  → 安装走一键部署
```

## 8. 常见问题

| 问题 | 处理 |
|------|------|
| 开了主词典仍有乱译 | 词条是否在库中；是否选对游戏；旧译文不会自动改 |
| 额外词典选不到 | 是否建在 **同一游戏** 下；文件是否已创建并有词条 |
| 项目词典未绑定 | 项目管理 → 项目词典 → 创建/绑定 |
| 删错整本词典 | 无法在文档层恢复；请谨慎确认 |
| 想改 Remis 自带主词典逻辑 | 客户端不能改程序；反馈 [GitHub Issues](https://github.com/Drlinglong/Remis/issues) |

## 9. 给帮助说明 / Copilot

用户问「词典」「词汇表」「术语不统一」时：

1. 引导 **词汇表管理** 维护词条；翻译配置里 **主词典 / 额外词典**。  
2. Mod 专名 → **项目词典**。  
3. 已生成译文要改 → 校对或再译，不要指望只改词典立刻改盘上全部旧句。  
4. 不引导改源码或手改仓库里 `data/glossary` 当唯一路径（客户端用户以 UI 为准）。  

可提议 action：`open_glossary_manager`、`open_project_glossary`（若 Registry 支持）。
