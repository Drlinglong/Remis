# Remis 小助手：问问题与安排工作流

> 3.1.0 中该功能仍是隐藏工程预览，普通打包用户暂时看不到。下一版本计划向普通用户开放。

Remis 小助手把 Copilot 和 Agent 放在同一个聊天框里：

- 问“这个功能怎么用”时，它像进阶版新手教学；
- 说“帮我完成这个目标”时，它会整理成 Remis 工作流计划。

## 你可以怎样说

例如：

- “增量翻译和初次翻译有什么区别？”
- “这个变量错误是什么意思？”
- “我要汉化这个 Mod。”
- “检查这个项目有没有更新，有的话先挖新词，再做增量翻译。”
- “刚才的任务哪些完成了，哪些失败了？”

不必使用 API、路由或数据库等技术词。

## 回答问题

小助手优先依据 Remis 用户文档回答，并可能结合当前页面的安全摘要给出下一步按钮。

如果文档没有覆盖，它应该明确说明不确定，而不是编造菜单、文件路径或已经执行的操作。

不要把 API key、Cookie 或其它秘密粘贴进聊天。需要配置模型时，请在 Remis 设置页面填写。

## 安排工作流

当你提出执行目标时：

1. 小助手先检查必要的项目状态；
2. 把目标拆成普通用户能理解的步骤；
3. Remis 检查这些步骤是否属于已注册功能；
4. 页面展示项目、语言、模型、写入范围、费用风险和执行顺序；
5. 你批准后，Remis 才开始真正执行。

小助手自己不会直接修改本地化文件。真正的写入由初次翻译、增量翻译、格式修复、部署等
原有功能完成。

## 哪些操作会再次询问

只读回答、查看状态和打开页面通常不需要确认。

以下操作必须让你确认：

- 调用可能收费的模型；
- 创建项目或复制 Mod；
- 写入／覆盖翻译成果；
- 再次运行可能收费的任务；
- 修复并写回；
- 部署；
- 删除成果、元数据或假本地化；
- 修改原始 Mod／创意工坊文件的特殊操作。

如果批准后计划的模型、步骤或写入范围发生变化，Remis 应重新询问，不能静默扩大授权。

## 怎样判断真的完成

小助手说“任务已启动”只代表后台已经开始，不代表工作完成。

可靠的最终结果应包含：

- 准确任务 ID；
- 每一步是成功、跳过、部分成功还是失败；
- 已经生成或保留了什么成果；
- 哪些内容还需要检查；
- 下一步可以去哪里。

真实状态以 Remis 持久化任务和业务结果为准。小助手不能仅凭聊天记忆声称已经完成。

## 它不会做什么

- 不直接编辑你的 yml 或其它文件；
- 不改 Remis 源码；
- 不运行任意系统命令；
- 不操作 Steam 账号或 Paradox 启动器；
- 不偷偷花钱、部署或删除；
- 不使用白名单以外的能力；
- 不把部分失败说成全部成功。

## 当前预览能力

3.1.0 开发态已经能：

- 回答 Remis 使用问题；
- 给出白名单内的导航按钮；
- 只读检查一个 Mod 文件夹；
- 生成“创建项目并启动初次翻译”的计划；
- 在用户批准后启动该翻译任务。

目前还不能在一份通用计划中可靠串联“检查更新 → 新词挖掘 → 增量翻译 → 生成封面”等
任意多步骤工作流，也没有在聊天中持续等到所有任务结束并生成最终总结。
