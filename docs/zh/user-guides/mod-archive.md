# 模组档案馆：整理、发布与审阅

> 侧栏入口：**「质量与术语 → 模组档案馆」**。

模组档案馆把源文件中的术语与叙事信息整理成可追溯的项目档案。它不会直接改写模组源文件；术语候选仍需在「审判庭」中由你确认。

## 1. 选择分析范围

分析设置提供两个范围，并由同一个工作流维护：

- **仅整理术语**：发现候选术语，完成后进入审判庭。
- **整理完整档案（术语、人物、地点、组织与事件）**：额外生成项目摘要、实体摘要与事件摘要，并发布一份不可变档案版本。

如果之后从“仅整理术语”切换到完整档案，Remis 会重新读取源文件。源文件快照、分析范围和上游版本会保留在发布版本的元数据中。

## 2. 查看已发布档案

「已发布档案」页签是只读视图，显示：

- 发布版本、源快照、分析范围、模型和时间；
- 项目、实体与事件摘要；
- 如果存在人工覆盖，显示合并后的有效值与覆盖值；
- 按需展开的来源引用、来源路径和证据 provenance 标签。

展开追溯信息后，还可以查看候选治理结果。Remis 会先归并大小写、Unicode、首尾标点以及
英文开头 `a`／`an`／`the` 的确定性别名，再由程序计算提及数、来源条目覆盖、local unit
覆盖和事件链覆盖。展示名称仍保留原始冠词；规范化键只用于匹配，不能把 `The Worm` 与
`Worm-in-Waiting` 这类语义相关但词面不同的名称强行合并。

候选按用途分为实体、词典术语、命名短语和偶发概念，并分成核心、次要与仅审计三档：

- 核心实体可以生成摘要；核心词典术语或命名短语仍不会被伪装成实体摘要；
- 次要候选可以进入审判庭，但默认不生成长摘要；
- 只出现一次的普通描述性概念默认仅保留审计证据，在追溯区折叠显示，不占用翻译上下文。

模型只提出原始词面、候选类型和语义规范名建议。所有覆盖数字、分档与投递资格都由后端
根据已归并的证据计算。人工覆盖可以调整候选类型、分档与资格；界面会同时显示真实类型和
治理分档，不把“已提升”误写成“模型确认”。

发布版本不会在此页签中编辑。点击「从此版本开始草稿」后，Remis 会以当前显示版本为基线创建独立草稿。草稿里可以按条目调整摘要、首选名称/别名、实体类型、事件归属和关系修正，并附加备注；已有人工覆盖会明确标为“已继承”。

保存只写入草稿。点击「准备发布新版本」后，必须再次确认，因为发布会创建一个新的不可变子版本；原来的发布版本仍然保持不变，页面会刷新到新的版本并显示父版本 ID。这里没有删除或清除值的操作：当前后端没有墓碑语义，若需要移除内容，应等待后续独立设计。

如果当前源快照与发布版本不一致，页面会标记为“已过期”。如果只有元数据或部分摘要可用，页面会保留现有内容并标记为“部分可用”，不要把它当作完整档案使用。

## 3. 审判庭

「审判庭」仍专注于候选术语的逐条裁决。完整档案分析完成后可先检查已发布摘要，再回到审判庭批准、驳回或处理重复术语。

`glossary_eligible` 只表示候选可以进入审判流程，不表示已经批准。只有你在审判庭明确
批准后，词条才会写入项目词典并参与正式词典注入。
