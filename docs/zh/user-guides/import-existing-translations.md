# 导入已有译文：翻译上载与半成品

> 当你 **磁盘上已经有汉化文件**（自己以前翻的、别人做了一半的、旧工具导出的），需要让 Remis **认账** 并写入项目归档时，用本文。  
> 界面按钮名：**「翻译上载」**。

这不是「从零 AI 全翻」；也不是改 Remis 源码。它是把 **已有译文同步进项目数据库（归档）**，方便：

- 之后跑 **[增量翻译](incremental-update.md)** 时能复用这些句子  
- 在项目管理中看到正确的归档语言与历史  

---

## 1. 什么时候需要翻译上载？

| 场景 | 要不要上载 |
|------|------------|
| 刚在本机用 **初次翻译** 完整跑完 | 通常流程已建立归档；不必重复上载（除非你又手工改了大量磁盘文件想同步回去） |
| **别人 / 旧版本** 的汉化包，想继续用 Remis 维护 | **需要** 上载 |
| 半成品：只翻了一部分 yml，想接着做增量或校对 | **需要** 上载（确保路径与语言对应正确） |
| 只想进游戏玩、永不更新 | 可只部署文件；但以后更新会痛，仍建议纳入项目并上载 |

界面说明大意：

> 将磁盘上已有的翻译文件成果同步到数据库（归档），以便未来增量更新时自动服用这些内容。

---

## 2. 操作前检查清单

1. 已在 **项目管理** 中有一个对应此 Mod 的 **项目**（没有则先 [创建项目](getting-started.md)）。  
2. 项目的 **游戏、源语言** 正确。  
3. **翻译输出 / 译文所在目录** 已挂到该项目（项目管理里可「管理路径」；经 Remis 译出的目录常会自动加入）。  
4. 译文文件结构符合该游戏本地化习惯（语言子目录、`*_l_语言.yml` 等），且编码尽量保持 P 社常用方式（优先用 Remis 读写，避免记事本另存坏编码）。  
5. 你知道这些译文对应的 **目标语言**（如简体中文）。

路径或语言对不上时，上载可能成功条数为 0，或归档了错误内容——上载前请打开目录确认。

---

## 3. 怎么做（客户端）

1. 打开 **「项目管理」**，选中目标项目。  
2. 进入 **「历史」** 相关区域（历史与归档基线、版本事件所在页签/面板）。  
3. 确认当前归档状态（是否已有目标语言、最近上载时间等）。  
4. 点击 **「翻译上载」**。  
5. 等待完成提示（例如成功上载的条数）。  
6. 再次查看 **已归档目标语言** 是否出现你的语言。  

上载完成后：

- 要跟新版原文对齐 → 去 **[增量翻译](incremental-update.md)**  
- 要人工改句子 → **校对**  
- 要修格式 → **智能工坊**（若可用）  
- 要进游戏 → **一键部署**（+ 假本地化）  

---

## 4. 和「归档项目」不是一回事

| 名称 | 含义 |
|------|------|
| **翻译上载** | 把 **译文文件内容** 写入数据库作 **翻译归档基线** |
| **归档项目**（档案馆） | 把整个 **项目** 从活跃列表封存，以后可恢复；**不是**「上传译文」 |

不要在需要「建立翻译基线」时，误点成「把项目丢进档案馆」。

---

## 5. 常见问题

| 现象 | 处理 |
|------|------|
| 增量仍说没有存档 | 确认上载成功；语言是否在「已归档目标语言」里；是否选错了项目 |
| 上载后增量几乎全是「新增」 | 新版源码路径是否正确；译文是否对应同一 Mod / 同一套 key |
| 半成品大量空行 / 英文残留 | 上载后可校对或再跑翻译；增量会把空译文、疑似漏翻计入待翻译（以预扫描说明为准） |
| 只有文件、从未建项目 | 先 [从零开始](getting-started.md) 建项目并管理好路径，再上载 |
| 想改 Remis 程序来「合并」 | 客户端不能改源码；流程内解决，或 [GitHub Issues](https://github.com/Drlinglong/Remis/issues) |

---

## 6. 给帮助说明 / Copilot

用户说「别人的汉化」「半成品」「已有 yml 怎么导入」时：

1. **先建/选项目并挂上译文路径**  
2. **项目管理 → 历史 → 翻译上载**  
3. 再谈增量 / 校对 / 部署  
4. 不要引导手改 SQLite 或源码
