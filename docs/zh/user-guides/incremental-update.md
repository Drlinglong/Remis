# 增量翻译：Mod 更新后怎么少翻

> 面向已经有过一次汉化成果、**原版 Mod 又更新了** 的用户。
> 增量翻译会 **复用未变化的译文**，只把 **新增 / 修改** 的条目送去 AI，省时间也省费用。

若你是第一次汉化：请走 **[从零开始](getting-started.md)** 的 **初次翻译**，不要从这里起步。

---

## 1. 增量 vs 初次：别走错门

| | **初次翻译** | **增量翻译** |
|--|--------------|--------------|
| 入口 | 侧栏「初次翻译」 | 侧栏「增量翻译」 |
| 前提 | 已在 **项目管理** 建好项目 | 同一项目已有 **归档基线** |
| 典型场景 | 从零翻整个 Mod | 创意工坊更新、作者发了新版本 |
| 行为 | 按配置做全量（或该次任务范围）翻译 | 对比新旧，**复用**旧译文，只翻变化部分 |

**没有归档就做增量** → 界面会提示存档缺失，对比失败。此时应：

- 从零：先 **初次翻译**；或
- 半成品 / 别人的译文：先 **[翻译上载](import-existing-translations.md)**。

---

## 2. 什么是「归档基线」？（必懂）

归档 = Remis 记在项目数据库里的「某次译文快照」，用来和 **新版原文** 做对比。

常见来源：

1. **初次翻译成功完成** 后自动/流程内写入的归档
2. **项目管理 → 历史** 里的 **「翻译上载」**（磁盘上已有译文写入库）
3. 以往增量跑完后的写回归档

在增量流程里你会看到类似信息：

- 检测到存档点 / 归档版本 / 条目数 / 最近上载时间
- **已归档目标语言** 列表（增量 **只支持已归档过的目标语言**）

项目历史上可确认基线是否建立；也可从历史区 **「前往增量更新」** 跳转。

## 3. 推荐操作步骤

### 3.1 准备新版源码

1. 让 Steam / 作者更新把 **新版 Mod** 落到本地（创意工坊缓存或你的拷贝）。
2. 记下 **新版 Mod 根目录** 路径（后面要选「新的源码目录」）。
3. 确认你要更新的仍是 **同一个 Remis 项目**（不要无故新建一个空项目，否则没有旧归档）。

> 界面说明倾向：用 **旧项目当基线**，把「新的源码目录」指到 **更新后的文件夹**（例如复制/更新后的创意工坊目录）。

### 3.2 打开增量翻译并选项目

1. 侧栏进入 **「增量翻译」**（或从项目历史点「前往增量更新」）。
2. **步骤 1 · 选择项目**：搜索并选中已有项目。
3. 确认游戏、源语言、目录名无误。

### 3.3 数据校验与配置（步骤 2）

检查并设置：

| 项 | 说明 |
|----|------|
| 归档是否可用 | 有存档点才能继续；没有则按提示去初次翻译或翻译上载 |
| **目标语言** | 只能选 **已归档过** 的语言 |
| **新版本 / 新的源码目录** | 指向 **更新后的原文 Mod 文件夹** |
| API 供应商与模型 | 与平时翻译相同；先在 **设置 → API** 配好 |
| 并发 / RPM / 批次 | 本次生效；本地模型宜偏低并发 |
| 断点续传 | 若检测到上次未完成任务，可选择从中断处继续 |
| 嵌入智能工坊 | 默认可开启：译完后做一轮格式修复（可另选校对模型） |

路径探测失败时，用浏览手动选中新版文件夹。

### 3.4 预扫描预览（步骤 3）

点 **「执行预扫描」**（或同等按钮），查看例如：

- **可复用**：旧源文一致且已有有效译文
- **新增待翻译**
- **修改待重翻**
- 文件级变更明细

请先看数字是否合理：

- 几乎全部「新增」而你只是小版本更新 → 可能 **指错了新目录** 或 **基线不对**
- 「可复用」为 0 且条目很多 → 暂停，回项目管理核对历史归档与路径

### 3.5 正式执行（步骤 4）

1. 确认预扫描无误后开始翻译（会调用 API，可能产生费用）。
2. 等待执行日志与进度（扫描源 → 读归档 → 比对 → 翻译 → 整理结果）。
3. 完成后检查输出目录、警告摘要、智能工坊导出的问题（若有）。
4. **一键部署**（需要时 **删除假本地化**），进游戏抽查。

### 3.6 Agent API：先做无费用预览

使用 Codex/Agent 时，可先调用
`POST /api/agent/projects/{project_id}/incremental-preview`，请求体例如：

```json
{
  "custom_source_path": "D:/Mods/MyMod-new",
  "target_lang_codes": ["zh-CN"]
}
```

`custom_source_path` 可省略。预览不需要 Provider 或 API Key，不调用模型，也不写项目、归档或输出；它返回整体 `summary`、包含平铺计数的 `per_language` 列表（其中各语言的 `deleted_entries` 列出已删除条目）、含 `dirty_entries` 的 `file_summaries`，以及 `fingerprint`、`source_path` 和 `source_language`。检查文件级结果和计数合理后，把该 `fingerprint` 填入 `/api/agent/jobs/plan` 的 `expected_preview_fingerprint`，使后续计划对应到已审核的预览。若源码或预览已变化，执行会拒绝过期预览；请重新预览并审核。

也可以用 `POST /api/agent/jobs/plan` 的增量 `dry_run: true` 做实际差异计算；这一步不调用 Provider。初次翻译的 `dry_run` 仍只是就绪检查。`GET /api/agent/jobs/{job_id}` 的 `result.metadata` 会包含 `incremental_preview` 和 `diff_executed: true`。完成的任务可从同一响应的 `result.metadata.entry_summary` 与 `result.metadata.file_summaries` 检查结果。请分开看**原文变化条目**、**实际提交模型条目**和**待人工复核条目**；它们代表不同范围，不能把源码变更数当作模型调用数。

预览优先使用作者原始 `Text`，并确认该列的语言。只有用户明确选择时，才使用 `Translation` 列作为翻译源。若项目归档基线是英文，不能静默切到西班牙语 `Text`；语言切换可能使全部条目看起来都已变化。新准备的源码可通过 `custom_source_path` 附加到旧项目；即使上下文模式设为 `none`，增量复用仍使用项目归档基线。Copilot 帮助可以依据本指南解释和引导该流程，但帮助模式本身不会执行增量预览或翻译。

## 4. 半成品 / 别人的汉化怎么办？

若项目 **从未在本机完成过初次翻译**，但磁盘上已有译文文件夹：

1. 先在项目管理建好项目并挂上正确路径（含译文输出/已有汉化目录，按你的项目配置）。
2. 打开 **项目管理 → 历史**，执行 **「翻译上载」**。
3. 上载成功后再进 **增量翻译**。

专文：**[导入已有译文（翻译上载）](import-existing-translations.md)**。

## 5. 常见问题

| 现象 | 可能原因 | 怎么做 |
|------|----------|--------|
| 未检测到翻译存档 | 无归档 | 初次翻译，或历史里 **翻译上载** |
| 没有可归档的目标语言 | 从未为该语言建过归档 | 先对该语言完成初次翻译或上载 |
| 预扫描几乎全是新增 | 新路径指错；或基线不是这个 Mod | 重选文件夹；核对项目 |
| 想改的语言不在列表里 | 该语言未归档 | 先初次翻译/上载该语言 |
| 任务中断 | 网络、配额、关机 | 有断点时开启 **断点续传** |
| 译完游戏里仍英文 | 部署/假本地化/加载顺序 | [假本地化](fake-localization.md)、[FAQ](faq.md) |
| 大批量回退原文 / API 警告 | Key、限流、模型能力 | [Provider 速查](provider-setup-index.md)、[日志](logs-and-diagnostics.md) |

---

## 6. 给帮助说明 / Copilot

用户说「Mod 更新了」「只翻新的」「增量」时：

1. 确认是否 **已有项目 + 归档**；没有则引导初次翻译或 **翻译上载**。
2. 引导侧栏 **增量翻译** 四步：选项目 → 校验路径/语言 → 预扫描 → 执行。
3. **优先内置流程**，不要让用户手改数据库或源码。
4. 完成后引导 **一键部署**，而非只给手动复制路径。
