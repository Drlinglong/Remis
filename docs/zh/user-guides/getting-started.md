# 从零开始：第一次汉化该怎么走

> 面向刚打开 **Remis 打包客户端** 的用户。
> **正确入口是「项目管理 → 创建新项目」**，不是一上来就点「初次翻译」。

「初次翻译」只会 **选用已经建好的项目** 来跑翻译流水线。
项目不存在时，翻译页没有可选对象，或你会误以为程序坏了。

---

## 0. 总览（先看这一张图）

```text
① 设置 API（可选但强烈建议先做）
        ↓
② 项目管理 → 创建新项目（选定 Mod 文件夹、游戏、源语言）
        ↓
③ 初次翻译 → 选中该项目 → 配目标语言与模型 → 开始翻译
        ↓
④ 一键部署（需要时删除假本地化）→ 游戏启动器启用
        ↓
⑤ （可选）校对 / 智能工坊修格式 / 词典微调
```

| 你想做的事 | 去哪里 | 不要先去 |
|------------|--------|----------|
| 第一次汉化一个新 Mod | **项目管理 → 创建新项目** | 直接「初次翻译」却没有任何项目 |
| 已经建过项目，要开翻 | **初次翻译** | 再创建一个重复项目（除非真的是另一个 Mod） |
| 原 Mod 更新了，只翻新增 | **增量翻译**（需已有归档基线） | 当成第一次全量「初次翻译」盲目重来 |
| 装进游戏 | **一键部署** + 必要时 **删除假本地化** | 先手动翻创意工坊目录（内置失败再用手动） |

---

## 1. 开始前准备

### 1.1 你需要有什么

- 已安装的 Remis 客户端
- 要汉化的 **完整 Mod 文件夹**（或 Steam 创意工坊里该 Mod 的目录）
- 至少一种可用的 AI 服务（云端 API Key，或本机 Ollama 等）

Mod 文件夹应是 **Mod 根目录**（里面通常有 `localization` / `localisation`、元数据等），不要只拷贝某一个 yml 文件。

创意工坊路径形态示意（数字因游戏和物品而异）：

```text
...\steamapps\workshop\content\<游戏ID>\<创意工坊物品ID>\
```

也可在创建项目时直接选这个目录；界面说明里写明了支持这种路径。

### 1.2 先配置 API（推荐第一步）

1. 左侧导航打开 **「设置」**
2. 进入 **API** 相关页签
3. 填好你要用的服务商、密钥、模型等
4. 若有连接测试，先测通再翻译

服务商怎么配：先看 **[Provider 配置速查](provider-setup-index.md)**（**设置 → API**），再按需打开 Ollama / 自定义接口等专文。

没有可用模型时，后面「初次翻译」会卡在调用阶段。

---

## 2. 第一步：在「项目管理」里创建项目（必须）

### 2.1 怎么进入

任选其一：

- **主页** 大按钮 **「开始新的翻译项目」** → 会进入 **项目管理**
- 左侧导航 **「项目管理」** → **「创建新项目」**

### 2.2 创建时要填什么

对话框标题一般为 **「创建新项目」**，常见字段：

| 字段 | 含义 | 注意 |
|------|------|------|
| **项目名称** | 你在列表里认的名字 | 可用 Mod 常见名，便于以后找 |
| **文件夹路径** | Mod 根目录或创意工坊目录 | 用「浏览」选，避免手打错 |
| **导入方式** | 见下表 | 大 Mod 常选「原位使用」 |
| **游戏** | Vic3 / Stellaris / HOI4… | 必须和真实游戏一致，校验规则不同 |
| **源语言** | 原文语言（如 English） | 假本地化清理也依赖「保留哪种原文语言」 |

### 2.3 导入方式怎么选？

| 选项（界面文案） | 含义 | 适合 |
|------------------|------|------|
| **复制到 Remis** | 识别 Mod 主目录后，把已知本地化目录和元数据 **复制** 到 Remis 工作区 | 想与原版目录隔离、体积不大的 Mod |
| **原位使用** | 识别主目录后 **直接使用该路径**，不整包复制 | **大型 Mod**、磁盘紧张、或你明确要对着原目录工作 |

两种方式都会先识别 Mod 主目录；选错游戏或源语言比选错导入方式更伤流程，请仔细确认。

### 2.4 创建成功后你会在哪？

- 项目管理列表里出现新项目
- 可打开项目看 **文件列表、状态概览、任务看板** 等
- 此时 **还没有完成翻译**；只是建立了「这个 Mod 在 Remis 里的档案」

项目页上通常有前往翻译的入口（提示类似 **「前往翻译页面开始翻译项目」**）。也可以左侧点 **「初次翻译」**。

---

## 3. 第二步：初次翻译（在已有项目上跑）

1. 打开 **「初次翻译」**
2. **从列表中选中** 刚才创建的项目（可搜索 / 按游戏筛选）
3. 进入配置：目标语言、API 供应商与模型、词典、是否嵌入智能工坊格式校对等
4. 开始翻译并等待任务完成
5. 在项目管理中确认输出目录 / 文件状态有进展

### 3.1 为什么不能跳过「创建项目」？

| 直接进「初次翻译」 | 先建项目再翻译 |
|--------------------|----------------|
| 没有项目可选，或不知道选谁 | 游戏、源路径、源语言已绑定 |
| 路径、语言容易每次重填不一致 | 后续校对、部署、增量更新都挂在同一项目上 |
| 像「一次性脚本」 | 符合 Remis 的项目管理模型 |

部分配置（如游戏、源语言）在翻译页是只读的，提示会写：**如需改动请返回项目管理页面**。

### 3.2 翻译结束后做什么？

1. 在项目里确认汉化输出已生成
2. 使用 **「一键部署」** 装到游戏可读的 mod 目录（步骤见 [一键部署](one-click-deploy.md)）
3. 若游戏里仍是英文 / 假中文：在部署流程里 **删除假本地化**（见 [假本地化说明](fake-localization.md)）
4. 启动器中启用 **原版 Mod + 汉化**，检查加载顺序

## 4. 可选后续（按需，不是第一天全做）

| 功能 | 何时用 |
|------|--------|
| **校对** | 人工改译文 → [校对](proofreading.md) |
| **智能工坊** | 批量扫格式问题并修复 → [智能工坊](agent-workshop.md) |
| **词汇表 / 词典** | 统一术语 → [词典与词汇表](glossary.md) |
| **增量翻译** | **已有归档** 的旧项目，Mod 更新后只处理新增/变更 → [增量翻译](incremental-update.md) |
| **翻译上载** | 手里已有半成品/别人的译文 → [导入已有译文](import-existing-translations.md) |
| **新词 / 词典治理** | 挖术语、审候选词（若你的版本开启了对应功能） |

第一天最小闭环建议只做：

**设置 API → 创建项目 → 初次翻译 → 一键部署（+ 假本地化）→ 进游戏看一眼。**

## 5. 常见岔路

| 情况 | 建议 |
|------|------|
| 初次翻译列表是空的 | 回 **项目管理** 创建项目；确认没有滤错游戏 |
| 点了主页「开始新的翻译项目」却不知道下一步 | 在项目管理点 **「创建新项目」**，填路径与游戏 |
| 想改游戏类型 / 源语言 | **项目管理 → 项目设置**，不要只在翻译页死磕 |
| Mod 更新了，只想翻新内容 | [增量翻译](incremental-update.md)；若无基线，先初次翻译或 [翻译上载](import-existing-translations.md) |
| 进游戏没中文 | [假本地化](fake-localization.md) + 加载顺序；优先 Remis 部署/清理 |
| 报错 / 闪退 | [日志与诊断](logs-and-diagnostics.md) |
| 校验红字看不懂 | [错误目录](error-catalog.md) |
| 想改 Remis 软件本身 | 客户端无法改源码 → [GitHub Issues](https://github.com/Drlinglong/Remis/issues) |

---

## 6. 给帮助说明 / Copilot 的引导原则

用户说「我要开始汉化 / 从零翻译」时：

1. **先**引导：**项目管理 → 创建新项目**（名称、路径、游戏、源语言、导入方式）
2. **再**引导：设置里 API 是否已配好
3. **然后**：**初次翻译 → 选中该项目**
4. **最后**：一键部署 / 假本地化 / 进游戏

不要默认：「打开初次翻译上传 zip 就能完事」——当前产品主路径是 **项目制**，不是无项目的一次性上传向导。
