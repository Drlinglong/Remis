# 智能工坊：扫描与修复格式问题

> 侧栏入口：**「智能工坊」**。  
> 用 AI **扫描** 项目本地化里的格式类问题，并生成 **可预览、可应用** 的修复建议。  
> 说明文案大意：*用 AI 扫描本地化问题，并生成可直接应用的修复建议。*

它修的是 **变量、标签、键格式、标点残留** 等脚本/格式问题，**不是** 文风润色或错别字文学批评。  
文风与译名请用 [校对](proofreading.md) 和词典。

---

## 1. 和「校对」「内嵌修复」的关系

| 能力 | 在哪 | 做什么 |
|------|------|--------|
| **智能工坊（本页）** | 侧栏独立流程 | 选项目 → 扫描 → 看摘要 → 批量/单条修复 |
| **内嵌智能工坊** | 初次/增量翻译配置里 | 翻译结束后自动跑一轮格式修复（默认可开） |
| **格式校对（项目管理）** | 项目内页签 | 看问题记录、刷新、跳转工坊 |
| **校对页验证** | 校对 | 当前文件人工改 + 验证 |

推荐节奏：

```text
翻译完成（可开内嵌工坊）
  → 仍有问题：打开智能工坊扫描并修复
  → 修不好的条目：手动校对
  → 一键部署进游戏
```

问题类型白话见 [错误目录](error-catalog.md)。

---

## 2. 使用前准备

1. 已有 **项目** 且已有译文（初次翻译、增量或 [翻译上载](import-existing-translations.md)）。  
2. 在 **设置 → API** 配好可用模型（见 [Provider 速查](provider-setup-index.md)）。  
3. 知道这是 **会调用 API、可能产生费用** 的操作（开始修复前界面会提示）。

---

## 3. 四步流程（与界面 Stepper 一致）

### 步骤 1：选择项目

- 搜索项目名 / 路径，可按游戏筛选。  
- 点选要修复的项目卡片。  
- 工坊 **基于现有项目**，没有项目请先 [从零开始](getting-started.md)。

### 步骤 2：项目信息 → 扫描

- 查看源语言、已归档目标语言、最近翻译时间、条目数等。  
- 点 **「扫描项目错误」**。  
- 说明：工坊会 **优先读取上次保存的扫描结果**；没有缓存再直接扫文件。需要最新结果时用 **重新扫描**（若提供）。

### 步骤 3：扫描摘要

- 查看 **问题条目数**、是否来自缓存。  
- 选择 **LLM 提供商** 与 **AI 模型**。  
- 可调性能：每批条数、并发、RPM（本地模型建议偏低）。  
- 浏览 **错误类型分布**、**文件级错误明细**。  
- 确认后点 **「开始修复」**（将调用 API）。

单条操作（在明细里）：

| 按钮 | 作用 |
|------|------|
| **分析并修复** | 打开 AI 建议弹窗，可预览差异后 **应用修复** 或放弃 |
| **手动校对** | 跳到校对页对应 key，人工改 |

### 步骤 4：执行修复

- 查看进度、日志、已修复 / 仍失败数量。  
- 结束后可对仍失败的条目再扫、单条修，或转校对。  
- 有报告路径时按界面提示查看。

## 4. 应用修复时注意

弹窗常见内容：

- AI 分析报告  
- 修复前 / 修复后差异  
- 原文上下文  
- 技术标签校验  

请你：

1. **看一眼** 变量 `$...$`、`[...]`、颜色/格式结束符是否仍在。  
2. 不合理就 **放弃** 或 **重新生成**，不要盲目全开。  
3. 批量「开始修复」适合格式问题集中时；关键剧情句可事后用校对抽查。

修复写回后，建议在工坊或项目格式校对里 **再扫/刷新**，确认问题减少（闭环：扫 → 修 → 复扫）。

---

## 5. 常见问题

| 现象 | 处理 |
|------|------|
| 未发现错误 | 当前规则下格式正常；文风问题请去校对 |
| 一直用「上次扫描结果」 | 改过文件后应 **重新扫描** |
| 修复后问题又出现 | 未写回成功、扫的不是同一输出目录、或假阳性；查路径与日志 |
| API 失败 / 限流 | 检查设置页 Key；降低并发/RPM |
| 想修「译得不够雅」 | 工坊不负责；用校对 + 词典 |
| 列表无项目 | 先建项目并完成翻译/上载 |

## 6. 给帮助说明 / Copilot

用户说「变量坏了」「格式一堆红」「智能工坊」时：

1. 引导 **智能工坊** 四步；强调先选对项目。  
2. 批量修前确认模型已配置；提示费用。  
3. 修完建议 **复扫**；搞不定的 → **手动校对**。  
4. 进游戏问题 → [一键部署](one-click-deploy.md) / [假本地化](fake-localization.md)，不要和格式修复混为一谈。  
5. 不引导改 Remis 源码。

可提议的 action（实现侧白名单）：`open_agent_workshop`、`scan_project_issues`、`start_workshop_fix`（写操作须确认）等——以 Registry 为准。
