# 校对：怎么改译文

> 侧栏入口：**「质量与术语 → 校对」**。
> 用于 **人工阅读、修改、保存** 已翻译文本，并可顺带跑 **格式验证**。
> 不是从零建项目的入口——请先有项目与译文（见 [从零开始](getting-started.md)）。

---

## 1. 校对适合干什么？

| 适合 | 不太适合（请用别的功能） |
|------|--------------------------|
| 改某一句/某一文件的译法 | 第一次创建项目 → [从零开始](getting-started.md) |
| 统一某事件的语气与专名 | 批量修变量/颜色标签 → [智能工坊](agent-workshop.md) |
| 保存前确认格式是否明显坏掉 | 进游戏安装汉化 → [一键部署](one-click-deploy.md) |
| 从工坊/项目管理跳进某条 key | 整包只翻更新部分 → [增量翻译](incremental-update.md) |

项目管理里文件旁常有 **「前往校对页面校对此文件」**；智能工坊问题旁有 **「手动校对」**，可深链到具体条目。

---

## 2. 推荐操作顺序

1. 左侧打开 **「校对」**。
2. **选择项目 / Mod**（下拉或选择器）。
3. 选择 **目标语言**（若界面提供）。
4. 选择要校对的 **文件**。
5. 在编辑区修改 **最终定稿**（可编辑栏）。
6. 需要时点 **「验证」** 看格式问题。
7. 点 **「保存」** 写回磁盘上的译文文件。
8. 有未保存修改时离开页面，会提示保存 / 放弃 / 保留草稿。

---

## 3. 界面在干什么？（三栏与模式）

常见为 **三栏编辑器（补丁模式）**：

| 栏（界面文案） | 作用 | 能否当「最终结果」改？ |
|----------------|------|------------------------|
| **原文 (参考)** | 磁盘上的原始语言文本 | 参考，不是你的交付物 |
| **AI 初稿 (参考)** | 数据库里当初 AI 译出的结果 | 参考 |
| **最终定稿 (可编辑)** | 磁盘上 **已翻译文件** 的当前内容 | **在这里改并保存** |

### 补丁模式（很重要）

- 系统按 **Key** 定位条目，保存时主要把你对 **Value（译文内容）** 的修改「缝」回文件。
- **不要改 Key 指望它生效**：对 Key、注释、无关格式的改动在保存时往往被 **忽略**。
- 若你改了 Key 仍点保存，可能弹出警告：确认后也只会保留 Value 变更。

一句话：**改句子内容，别改键名。**

---

## 4. 验证 vs 智能工坊

| | **校对页「验证」** | **智能工坊** |
|--|-------------------|--------------|
| 目的 | 当前文件/上下文的格式检查 | 项目级扫描 + AI 尝试修复 |
| 操作 | 人工看着改 | 可批量「开始修复」或单条分析 |
| 之后 | 你自己保存定稿 | 可跳转回校对手改仍失败的条目 |

校验红字含义见 [错误目录](error-catalog.md)。
批量修格式优先 [智能工坊](agent-workshop.md)。

项目管理里也有 **「格式校对」** 类页签：查看问题记录、刷新检查、**打开智能工坊**——与侧栏工坊是同一类能力的不同入口。

## 5. 保存、草稿与冲突

| 提示 | 含义 | 建议 |
|------|------|------|
| 未保存修改 | 定稿已改但未写盘 | 保存后再离开；或明确放弃 |
| 会话草稿恢复 | 上次未写完的编辑被找回 | 检查是否仍适用后保存 |
| 文件已在 Remis 外部变化 | 你在外部编辑器改过同一文件 | **从磁盘重新加载**，再决定是否保留本地草稿 |
| 变量标记变化警告 | `$...$` / `[...]` 等可能被改坏 | 对照 [错误目录](error-catalog.md)；确认无误再「仍然保存」 |
| 草稿冲突 | 草稿创建后磁盘又变了 | 优先使用磁盘新版本，避免旧草稿盖新文件 |

有未保存内容时关闭窗口，客户端也可能拦截并询问。

---

## 6. 两种使用方式（若界面有页签）

| 模式 | 用途 |
|------|------|
| **文件模式** | 按项目文件列表系统校对（主路径） |
| **自由模式** | 更灵活的粘贴/试验（以你版本界面为准） |

日常汉化以 **文件模式 + 最终定稿** 为主。

---

## 7. 常见问题

| 问题 | 处理 |
|------|------|
| 列表没有项目 | 先 [创建项目并翻译](getting-started.md) |
| 保存了但 Key 改动没了 | 正常：补丁模式只保留 Value |
| 验证一堆红字 | 先看 [错误目录](error-catalog.md)；批量修走工坊 |
| 进游戏还是英文 | 校对只改文件，还需 [部署](one-click-deploy.md) / [假本地化](fake-localization.md) |
| 想改 Remis 软件 | 客户端不能改源码 → GitHub Issues |

---

## 8. 给帮助说明 / Copilot

用户说「校对」「改某一句」「手改 yml」时：

1. 引导侧栏 **校对** → 选项目与文件 → 改 **最终定稿** → **保存**
2. 强调 **不要改 Key**
3. 格式批量问题 → **智能工坊**；进游戏 → **一键部署**
4. 不要让用户绕过 Remis 去乱改源码或手删半套文件（除非部署失败后的备用步骤）
