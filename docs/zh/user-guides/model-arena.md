# 模型竞技场：正式翻译前比较候选模型

> 侧栏入口：**翻译工作流 → 模型竞技场**。

Model Arena 用当前 Mod 的少量真实文本，让两个或三个模型生成匿名候选。你亲自比较这些
候选，再决定正式翻译时想用哪个模型。Remis 不会替你宣布冠军。

## 什么时候值得使用

建议在新项目开始翻译前使用，尤其是：

- 你有两个或三个可用模型，不确定该选谁；
- 你想判断更贵的模型是否真有可见收益；
- 这个 Mod 有特殊文风、专名或格式；
- 你换了模型或供应商，想先看小样。

以下情况可以直接跳过：

- 你只有一个模型；
- 你已经信任固定模型；
- 项目很小、文本很简单；
- 你不想为比较产生额外调用。

竞技场不是初次翻译或增量翻译的必经步骤。

## 创建试译草稿

1. 选择项目和目标语言。
2. 选择两个或三个不同的供应商／模型组合。
3. 保持默认 6 条样本，或在 3–12 条之间调整。
4. 决定是否沿用项目上下文和已绑定词典。
5. 点击创建草稿。

创建草稿不会调用模型。Remis 会展示：

- 实际抽到的源文本；
- 样本特征和随机 seed；
- 词典快照；
- 参赛模型数量；
- 预计请求数量。

不满意可以重新抽样，或返回修改配置。

## 确认并开始

点击开始后，确认弹窗会再次显示模型数、样本数和预计请求数。费用无法可靠估算，因此
Remis 会明确显示“费用未知”。只有勾选批准后才会真正调用模型。

参赛者会串行翻译同一批样本。Remis 不会因为某个模型失败而偷偷换供应商或模型。

## 匿名比较

至少两个模型成功返回后，逐条比较候选：

- 选择你认为更好的版本；
- 或选择平局；
- 或选择全部不满意；
- 无法可靠比较时标为无法判断；
- 可以补充偏好理由和备注。

模型身份、格式统计和耗时会保持隐藏，直到全部样本提交选择并完成揭晓。你可以在完成前
回来修改已保存的选择。

## 某个模型失败

Remis 会保留其它模型已经返回的结果并显示警告。你可以明确确认后，只重试失败模型。

三人局失败一人时，剩下两份成果仍然可以比较和完成。两人局失败一人，或三人局只成功
一人时，不足两份候选；当前 3.1.0 仍可能允许用“无法判断”完成，但可靠做法是先重试，
不要把单份输出当成模型比较结论。

## 怎样完成

每条样本都必须有一项有效决定，才能点击完成并揭晓。平局、全部不满意和无法判断也算
有效决定，不需要硬选一个赢家。

完成后可以查看：

- 各模型被选择的次数和偏好率；
- 用户填写的偏好理由；
- 平局与全部不满意次数；
- 硬格式错误及受影响样本；
- 请求数量、耗时和失败码；
- 每条样本的原文与各模型译文。

这些只是本次项目小样的个人偏好，不是全局排行榜。

## 接下来怎么做

竞技场不会自动：

- 修改项目默认模型；
- 把候选写进翻译文件；
- 启动初次翻译或增量翻译。

请根据结果返回正式翻译页面，亲自选择供应商和模型。直接跳转或带回选择的提示目前尚未实现，是未来可选增强。

## 本地历史、导出和删除

每次竞技场的候选、投票、格式结果和必要执行证据会保存在本地历史中。保存证据不代表
你批准某份候选成为正式译文。

导出步骤：

1. 点击“检查并导出结果”；
2. 选择包含正文的证据包，或不含正文的摘要模式；
3. 阅读精确 JSON 预览；
4. 明确确认后再写出文件。

Remis 不会自动上传结果。导出会排除或脱敏密钥、账号、API 地址、文件路径和独立推理
字段。删除某次历史前也需要确认。

## 常见问题

| 问题 | 处理 |
|---|---|
| 为什么默认只有 6 条 | 这是控制成本的代表性小样，不是统计 benchmark |
| 可以只选一个模型吗 | 不可以；竞技场需要 2 或 3 个不同组合 |
| 没投出唯一赢家怎么办 | 平局、全部不满意和无法判断都是正常结果 |
| 一个模型失败怎么办 | 三人局剩两份可继续比较；不足两份时先确认并重试 |
| 竞技场结束后模型会自动生效吗 | 不会；回正式翻译页手动选择 |
| 历史里为什么保存所有候选 | 用于本地复核，不等于采用为正式译文 |
| 会自动把内容传到 GitHub 吗 | 不会；导出后是否分享由你决定 |
