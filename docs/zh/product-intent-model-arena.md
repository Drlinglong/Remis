# Model Arena：产品意图契约

这份文档描述 Remis 为什么提供 Model Arena、用户怎样完成一次有效比较，以及竞技场结果
绝不能被系统自动扩展成正式翻译决定。当前实现与差距见
[Model Arena 开发契约](developer/model-arena-contract.md)。

## 文档状态

- 产品状态：稳定正式功能；3.1.0 是首个正式版本
- 适用范围：正式翻译前，用项目真实样本比较 2 或 3 个模型
- 产品决定人：玲珑
- 首次确认：2026-07-30
- 当前方向：观察真实使用效果并维护稳定性，暂不承诺功能扩展
- 用户指南：[模型竞技场](user-guides/model-arena.md)

## 用户为什么需要它

Model Arena 主要帮助用户在正式翻译一个 Mod 前决定使用什么模型。它不是比较某一句谁更
聪明；单句或少量条目只是来自当前项目的样本，最终问题是：

> 对这个 Mod、这个目标语言和当前配置，我更愿意使用哪个模型？

它也允许好奇的用户观察不同模型的差异，但好奇心不是自动替用户选模型的理由。

## 什么时候使用

Remis 可以把 Model Arena 作为新项目正式翻译前的建议步骤，尤其适合：

- 用户同时拥有两个或三个可用模型；
- 不确定更贵的模型是否值得；
- 项目有明显的专名、文风或格式要求；
- 更换供应商、模型或翻译配置后想先看小样。

它不是必经步骤。只有一个模型、已经信任自己的固定模型，或项目很小且文本非常简单时，
用户完全可以跳过。用户始终拥有最终决定权。

## 用户真正要得到什么

竞技场的产物是几组可并排判断的候选译文和一份个人偏好记录，不是 Remis 宣布的“冠军
模型”。用户可以选择某个候选、平局、全部不满意或无法判断。

结果页可以汇总偏好、理由、格式硬错误和耗时，但不得把少量样本包装成全球排行榜、统计
结论或自动推荐。

## 低成本抽样

大型项目不需要整本试译。默认从当前项目抽取 6 条有代表性的文本，让每个参赛模型翻译
同一批内容，避免账单失控。

当前实现允许把样本数调整为 3–12 条；这是高级选择，不改变“少量样本、个人判断”的
定位。Remis 无法可靠估算实际费用，必须明确显示费用未知。

## 开始前必须确认

真正调用模型前，用户必须亲眼确认：

- 当前项目；
- 目标语言；
- 每位参赛者的供应商和模型；
- 将发送给模型的样本文本；
- 样本数量与预计请求数量；
- 本次调用可能产生费用，但 Remis 无法给出可靠金额。

创建草稿和抽样不调用模型。用户明确确认后才能开始；重试失败模型也必须再次确认。

## 怎样才算成功

一次正式比较分成两个完成条件：

1. 至少两个参赛模型成功返回，竞技场才有可比较的候选；
2. 用户为全部样本提交选择后，才能完成并揭晓模型身份。

用户可以把某条判为平局、全部不满意或无法判断，这些都属于有效投票。用户不必选出唯一
赢家；“得到可判断的候选并完成自己的选择”就是成功。

## 模型失败时怎么办

单个模型失败时：

- 保留其它模型已经生成的结果；
- 明确警告哪些参赛者失败；
- 不静默换模型或供应商；
- 不用原文伪装成译文；
- 允许用户明确确认后只重试失败模型。

三人局中一人失败时，剩余两份成果仍可正式比较并完成。两人局失败一人，或三人局只有
一人成功时，因为不足两份候选，只能查看、重试或放弃，不能完成正式投票。

## 允许保存什么

Remis 可以在本地保存：

- 每个参赛模型的候选输出；
- 解析与格式检查结果；
- 用户投票、理由和备注；
- 供应商、模型和非秘密配置快照；
- 用于复核的请求与事件记录。

这类本地证据不等于用户批准某个候选成为正式译文。竞技场不能写入项目翻译文件。

## 系统绝不能偷偷做什么

Model Arena 绝不能：

- 自动把得票较多的模型设为项目默认模型；
- 自动开始初次翻译或增量翻译；
- 把候选译文写入正式翻译成果；
- 静默替换失败的供应商或模型；
- 自动上传、分享或导出结果；
- 在投票完成前揭晓模型身份；
- 用格式统计覆盖用户的主观选择；
- 因用户没使用竞技场而阻止正式翻译。

完成后可以提示用户“带着这个判断去选择正式翻译模型”，但提示不能自动执行任何动作。

## 导出与分享

导出必须先展示精确预览，再由用户确认。Remis 可以提供含项目文本的复核证据包，或不含
正文的摘要模式；两者都不能自动上传到 GitHub 或其它外部服务。

本地历史可以保存全部候选和用户决定。对外导出必须排除或脱敏密钥、账号、API 地址、
文件路径和独立思考／推理字段。

## 当前状态与非目标

Model Arena 是稳定正式功能，但 3.1.0 是它上线的第一个版本，仍需观察真实用户是否使用、
是否静默失败，以及样本是否真能帮助选择。

3.1.x 当前没有升级计划，只需要长期观察工作效果和优化稳定性。明确非目标包括：

- 自动选择或切换模型；
- 自动启动正式翻译；
- 建立全局模型排行榜；
- 承诺样本具有统计显著性；
- 自动发布竞技场数据；
- 提供可靠费用估算。

## 必须长期保留的契约测试

1. 草稿阶段不调用模型；开始和重试都必须明确确认。
2. 项目、语言、参赛供应商／模型和实际样本文本在调用前可见。
3. 默认样本数为 6，所有参赛者收到同一冻结样本和配置。
4. 至少两个参赛者成功后才允许正式投票；不足两份成果时只保留结果、警告和重试入口。
5. 所有样本提交有效投票后才允许完成并揭晓。
6. 投票前模型身份、格式错误和耗时保持匿名。
7. 结果不会改变项目默认模型、写翻译文件或启动翻译。
8. 本地历史保存候选证据；导出先预览、再确认，且不自动上传。
9. 未知供应商不被静默替换，失败输出不回退原文。
10. 删除竞技场历史需要确认并只删除该次运行的数据。
