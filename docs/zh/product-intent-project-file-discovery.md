# 项目文件发现与翻译上载：功能意图契约

这份文档描述“用户为什么点击这个功能、系统允许做什么、绝对不能做什么”。
它是产品意图，不是当前实现说明；实现和测试必须服从这里的边界。

## 刷新文件

用户把外部翻译成果复制到本机，或在 Remis 外更新了 MOD 文件，希望 Remis
重新看到磁盘现状，以便继续初次翻译、增量翻译或人工校对。

- 触发：用户点击“刷新文件”，或界面重新请求项目文件列表。
- 读取：项目注册信息、sidecar 中配置的翻译目录和文件状态、磁盘文件。
- 返回：本次发现的文件清单、数量、实际扫描目录和逐目录告警。
- 允许写入：无。
- 禁止写入：`project_files`、翻译归档、源版本、翻译条目、看板任务、历史记录。
- 失败语义：目录不存在、不可访问或权限不足时返回明确告警；不能将其解释为
  “成功扫描且为空”，更不能据此删除持久化数据。
- 一致性：连续刷新同一磁盘状态应得到同一文件 ID 和等价清单。

## 文件看板状态

文件任务由当前磁盘清单临时投影得到。显式移动任务时，只更新项目目录内的
`.remis_project.json`。打开看板、请求文件列表或刷新文件不得创建、修复或重写
sidecar。文件状态不是翻译内容，不进入 SQLite 的 `project_files` 表。

## 翻译上载

用户确认当前翻译成果可以成为后续增量翻译和版本比较使用的正式基线。

- 这是项目管理中把本地化内容写入翻译归档数据库的唯一入口。
- 上载前必须从磁盘重新读取待上载文件，并明确返回上载结果。
- 成功后可以创建源版本、源条目和翻译条目；部分失败必须逐文件报告。
- “刷新文件”“打开项目”“查看看板”“修改翻译目录”不能隐式执行上载。

## 必须长期保留的回归测试

1. 刷新存在目录：返回清单，repository、archive、kanban 写方法均未调用。
2. 刷新缺失或不可访问目录：返回告警，不删除任何旧数据。
3. GET 文件列表与 GET 看板：不创建或修改 `.remis_project.json`。
4. 移动文件任务：只改变 sidecar；遗留 `project_files` 行保持不变。
5. 翻译上载：只有显式上载路由能增加归档版本和翻译条目。

## 未来意图文档的最小模板

每个副作用容易被误解的功能，只需写清八项：

1. 用户意图；
2. 触发入口；
3. 允许读取；
4. 允许写入；
5. 明确禁止的副作用；
6. 需要确认的边界；
7. 失败与半成功如何呈现；
8. 用哪些契约测试锁住。
