# 官方参考语料库：产品意图契约

这份文档说明 Remis 为什么建立本地官方参考语料库、它怎样帮助翻译，以及扫描、更新和删除必须遵守的产品边界。具体操作见[官方参考语料库用户指南](user-guides/reference-library.md)，实现事实见[开发契约](developer/reference-library-contract.md)。

## 文档状态

- 产品状态：Issue #208 已实现，等待随 3.1.7 后续维护版本发布
- 适用范围：Remis 支持的 Paradox 游戏及用户本机安装的官方本地化文件
- 产品决定人：玲珑
- 当前方向：一次建库、跨翻译复用；维护过程可确认、可观察、可恢复查看

## 用户为什么需要它

大型 Total Conversion Mod 常直接复用大量官方文本。若这些条目仍交给模型翻译，不仅浪费时间和调用费用，还可能得到与官方术语不一致的译文。

Remis 因此可以从用户本机的官方本地化目录建立 SQLite 索引。之后在翻译前按 `(key, source language, source text, target language)` 精确匹配：来源身份和原文都一致时直接复用该目标语言的官方译文；冲突、缺少目标语言或原文不同则继续交给正常翻译流程。

## 用户操作模型

官方语料库是低频维护能力，入口位于“设置 → 系统维护”。

1. 用户点击“检测游戏并建立语料库”；
2. Remis 只读检测 Steam 库中的受支持游戏，并先列出游戏与实际本地化目录；
3. 用户选择要处理的游戏，看到“可能需要数分钟”的说明后确认；
4. 后台任务逐游戏报告扫描文件数、已索引条目数、当前阶段、成功或失败；
5. 用户离开设置页再回来，仍能恢复同一任务的状态；
6. 自动检测失败时，用户可以手动选择该游戏档案规定的 `game/localization` 或 `game/localisation` 目录。

已有语料库可以重建／更新。用户也可以“解除绑定并删除”，完整清除该游戏在 Remis 本地 SQLite 中的参考集合和条目；这不会删除或修改游戏文件。

## 系统绝不能偷偷做什么

- 不在应用启动、进入设置页或开始翻译时自动扫描游戏目录；
- 不把官方全量本地化文件打包进 Remis 安装包；
- 不扫描整块磁盘、不启动 Steam，只检查已登记的 Steam library 与 manifest；
- 不同时启动两个语料库写任务；重复请求必须复用正在运行的任务；
- 不因页面切换丢失进度，也不把部分失败显示成成功；
- 不按 key 单独命中，不在原文不同、目标语言缺失或存在冲突时强行复用；
- 不让 glossary、proofreading 或模型 repair 默认重写已经精确命中的参考译文；
- 不删除、移动或改写用户的游戏目录。

## 版本变化与过期索引

索引记录游戏、版本、目录统计指纹和内容指纹。检测到游戏版本或文件状态变化时，界面应提示可更新，但旧索引不会仅因版本标记变化就被强制禁用；实际复用仍以逐条精确匹配为安全条件。用户可以显式重建，数据库异常时也可以先删除再重建。

## 成功标准

- 一次确认可处理用户选择的所有已检测游戏，而不是每次点击只处理一个；
- 数分钟的建库过程持续提供真实进度，并能跨页面恢复；
- 初次翻译和增量翻译遵守同一精确匹配规则；
- 参考命中项不进入模型提交，界面可区分命中、提交、跳过和冲突；
- 删除是显式确认的本地数据操作，影响范围清楚且不触碰游戏文件；
- 非英语源语言、转义引号、Paradox 标签、重复键、相同源／目标文本和版本变化均有回归覆盖。
